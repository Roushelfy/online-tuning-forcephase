## 1. 问题与动作

对每个实例先做一次低成本观察（静态公式统计；可选再加一次固定 D 的短试跑），然后从下面三个动作中**只选一次**，从头启动正式求解：

| 动作 | 名称（`configs/solver_configs.json`） | 参数 |
| --- | --- | --- |
| D | `D` | `--phase=1 --forcephase=0`（默认原生相位：saved/target/rephase，初始正） |
| F+ | `Fplus` | `--phase=1 --forcephase=1` |
| F− | `Fminus` | `--phase=0 --forcephase=1` |

forcephase 会关闭 rephase，这一副作用属于所选策略包的一部分。I− 不是主动作。本轮不新跑 I−；只有在报告中需要时，才引用第一轮已有的 I− 记录作为补充对照，并单独标注。

本轮不使用内部控制补丁、多次切换、试跑状态续用、bandit/RL 或机制消融。

- 去重：同一 GBD isohash 的多个 hash 视为一个问题，五年合计 1,865 个独立问题。代表 hash 的取法是：第一轮运行过的成员优先；否则取最早年份的成员，同年取最小 hash。配额年取该问题的最早参赛年份，并记录全部参赛年份。

### 2.2 抽样规则

由 [scripts/three_way/sample_panel.py](../scripts/three_way/sample_panel.py) 实现，seed `20261022`，所有随机顺序都由 `sha256(seed:…)` 键确定，与迭代顺序无关：

1. **家族组**：沿用第一轮的保守别名表；`unknown` 家族按作者分组；再对同一 isohash 类的成员做并查集合并。
2. **资源条件**：GBD 未压缩字节数 ≤ 1 GB（`1e9`）。第一轮的上限是 100 MB；本轮放宽，以保留大规模层。上限之所以取 1 GB，是因为单次运行有 16 GB 内存限制，节点的 `/tmp` 又是内存盘，要同时容纳 LRAT 证明和 CNF 缓存。按配额年计，排除 16 / 22 / 16 / 12 / 2 个问题（2022 → 2026）。
3. **规模层**：在每个配额年的合格问题上，按 log10(1 + 子句数) 的三分位分为 small / mid / large。
4. **年度配额**：每年 100 题。先给每个家族组 1 题，剩余名额按 sqrt(组大小) 用最大余数法分配，单组不超过 10 题，也不超过该组的候选数。五年各有 54 / 55 / 61 / 78 / 79 个组，都少于 100，所以每个组都被覆盖；没有组触顶，也没有未用配额。
5. **组内抽样**：先保证每个存在的规模层各 1 题（层的先后顺序由 seed 决定），其余按固定秩补足。未入选的候选保留秩，作为预排替补：先在同一（年，组，层）内替换，其次在同一（年，组）内。只有在下载损坏、无法获取或违反资源条件时才替换，并记录理由。
6. 本次下载 500/500 成功，**没有发生替换**。

### 2.4 曝光与独立性（如实标注）

- 第一轮已对 2023–2026 年所有 ≤ 100 MB 的主赛道实例运行过 D/F+/F−/I−，seed 0，T = 300 s。面板中这样的实例共 364 个：dev 344 个，test 20 个。它们都是**已曝光证据**；第一轮的 test/t2026 不能再被称为新的盲测。
- 本轮 test 由 99 个实例、31 个组构成：79 个实例从未被运行过，44 个实例所在家族组在第一轮中从未被运行。test 与本轮 dev **家族不相交**。但其中 55 个实例所在的家族在第一轮出现过；20 个实例本身有第一轮结果；而且第一轮报告给出过部分家族的胜负，本 agent 读过这些报告。因此 test 的定位是“本轮家族不相交、以未运行实例为主的保留集”，**不是完全独立的新盲测**。最终报告按曝光分层给出结果。
- 偏向：以未曝光为优先，使 test 偏向 2022 年（45 题）和大规模层（58 题属于 large，49 题超过 100 MB）；dev 中超过 100 MB 的实例只有 12 个。最终报告按规模层和年份分开给出结果，不把 test 当作与 dev 同分布的样本。
- **数据边界**：S1–S2 的所有分析只读 dev（train + val）的记录。test 实例的固定动作、静态特征和试跑都要等到冻结之后才运行；那 20 个已有第一轮记录的 test 实例，在冻结之前不读取其记录。

## 3. 运行设置

- **固定动作**：`scripts/fprun.py`，实验 `configs/three_way/tw_dev_fixed.json`（S1a）和 `tw_test_fixed.json`（S3）。
  - 二进制 `build/fpc/cadical`：sha256 `6cf08469…`，CaDiCaL `c607304`（3.0.1），带补丁，控制器关闭，搜索与上游一致。
  - 运行政策：`--lrat=1` 证明，`--fpc=1` 遥测，seed 0（原始 CNF），T = 300 CPU 秒，内存 16,000 MB，每次运行固定在一个物理核上。
  - 节点：`cpu-low` 独占节点，每节点 48 个并发（与第一轮相同）。
- **复用**：run id 由内容寻址，覆盖参数、二进制、实例、seed、T、内存和证明政策。与第一轮完全相同的运行会自动复用，不重跑：dev 1,203 次中复用 1,032 次、新跑 171 次；test 297 次中复用 60 次（S3 时才读取）。
- **静态特征**：`build/tools/cnfprofile`（`tools/cnfprofile.c`，由 `scripts/three_way/build_tools.sh` 在容器内构建，gcc 13.4，二进制 sha256 `f3aa2e849f2557bbc59576734ef3cbe9ce3bd1b19269ea725437d49ae877be70`）读取与求解器相同的未压缩 CNF，单遍完成，计时包括它自己。
- **CPU 限额的执行方式**（试跑与 wrapper 正式求解共用 `twlib.run_budget`）：CaDiCaL 是单线程，CPU 时间增长不快于墙钟，所以每次休眠“剩余 CPU”（最多 1 s）后再读 `/proc` 检查。这样轮询开销很小，停止误差约 10 ms。
- **D 试跑**：`twlib.run_probe`。命令与 D 基线完全相同（同二进制，LRAT + 遥测），子进程 CPU 达到预算 b 时发 SIGTERM（CaDiCaL 会优雅停止并打印统计），之后再过 max(1, b) 秒仍未退出就 SIGKILL。dev 上的试跑由 `scripts/three_way/twrun.py probe` 运行；部署时 wrapper 调用的是同一个函数。
- **wrapper**：`scripts/three_way/select_solve.py`，只用标准库。由 `twrun.py wrap` 固定在一个核上启动；总 CPU 取 wrapper 整个进程树经 wait4 测得的值，包括 Python 启动、特征提取、试跑、推理和正式求解。正式求解从头开始，只得到剩余预算 T − 已用 CPU，其命令与对应的固定动作完全相同。
- **验证**：SAT 用 `checkmodel` 对照原始 CNF，UNSAT 用 `lrat-trim` 检查 LRAT 证明。检查器的 CPU 单独记账，不计入成本。试跑或 wrapper 给出的答案同样必须验证通过才算解出。

## 4. 计分与成本

- 单个实例：解出（在 T 内答出且验证通过）时，cost = CPU 秒；否则 cost = PAR2 = 600。wrapper 的 cost 是整个进程树的总 CPU。
- 状态分开统计：solved / timeout / memout / crash / error / wrong / unverified / missing。非 solved 一律按 600 计分，并逐项列出，不做静默删除。
- 主指标：mean PAR2、solved 数、观察开销（wrapper 的总 CPU 减去正式求解 CPU）、各动作被选中的次数、严重回退（定义见第 9 节）、逐年与逐家族表现。分类准确率只作辅助。
- **离线模拟**（只用于 S2 在 dev 上比较候选）：
  - 记 o = 静态特征 CPU + 试跑 CPU + Python 常数 κ。
  - 试跑解出：cost = o。
  - 否则选中动作 a：若 a 的完整运行解出且 o + c_a ≤ 300 − 0.1，cost = o + c_a；否则 cost = 600。wrapper 给正式求解的预算是 T − 已用 CPU − 0.1 s，留 0.1 s 给自身收尾，因此模拟中同样扣掉这 0.1 s。
  - κ = **0.08 s**：取自工程 smoke（6 个 train 实例 × 2 个占位模型，自适应轮询版本），即 wrapper 总 CPU 减去特征、试跑与正式求解 CPU 后的中位数 0.076 s，向上取整。
  - 最终收益**只以 S3 的真实 wrapper 运行为准**。

## 6. S1b：优势分组（规则先于分析冻结）

对每个 dev 实例：

1. 三次运行中任一状态不是 solved/timeout，记为 **invalid**，单独列出，不算任何动作获胜。
2. 三者都超时，记为 **all-timeout**，不指定标签。
3. 其余实例：设 best 为 cost 最小的动作（完全平手时按 D、F+、F− 的顺序取前者），second 为第二小的 cost，margin m = (c_second + 1) / (c_best + 1)。
   - m ≥ 1.5：记为 **best 动作的优势组**（D-adv、F+-adv、F−-adv）。再分两种子类型：exclusive 指只有 best 解出；faster 指 best 和第二名都解出、但 best 明显更快。
   - m < 1.5：记为 **close**，同时记录近优集合（满足 (c_a + 1)/(c_best + 1) < 1.5 的所有动作）。
4. 敏感性分析：再用 m 的阈值 1.2 和 2.0 各报告一次分组。

然后先比较各组的可观察特点，再训练任何模型：

- 静态特征（第 7 节）在各组中的分布：中位数和四分位，并给出每个优势组与其余实例之间的标准化中位差。
- 年份与家族：各组按家族、按年份的占比，以及收益是否集中在少数家族。
- 连续结果：r_F+ = log2((c_F+ + 1)/(c_D + 1))，r_F− 同理，在去除 all-timeout 的实例上计算。对每个特征给出它与 r_F+、r_F− 以及 r_F+ − r_F− 的 Spearman 相关，并给出**家族内**版本（在家族内中心化后再求秩相关），用来检查扣除家族差异后信号是否仍然存在。
- 试跑统计（三个预算）作同样的比较。只使用正式选择之前就能观测到的量。
- 已知的 SAT/UNSAT 只作事后分层。“正文字更多就选 F+、负文字更多就选 F−”只作为待检验的假说：报告 p_pos_lit_frac、p_var_bal_mean 与 r_F+ − r_F− 的关系，不预设它成立。

## 7. 特征

部署特征不包括家族名、年份、实例 ID、SAT/UNSAT 或终局结果，也不使用旧的 flip 特征。

- **静态特征**（`twlib.STATIC_FEATURES`，共 28 个）：
  - 规模：log 变量数、log 子句数、子句/变量比；
  - 子句长度：均值、标准差、log 最大值；
  - 子句长度分布：单元、二元、三元、≥4、≥10 的比例；
  - 极性与子句类型：正文字比例、Horn 比例、反 Horn 比例、全正子句比例、全负子句比例，以及二元子句中全正、全负的比例；
  - 变量极性偏置 b = (p − n)/(p + n)：均值、标准差、|b| 的均值，纯正、纯负、正多数、负多数变量的比例；
  - 出现次数：log 均值、变异系数、log(最大值/均值)。
- **试跑特征**（`twlib.PROBE_FEATURES`，共 24 个，D 试跑预算 b ∈ {0.1, 0.5, 2} CPU 秒）：
  - 搜索是否已开始；log 冲突数、log 决策数、log 传播数；log(冲突/秒)；决策/冲突；log(传播/决策)；
  - 固定变量比例、消去变量比例、学习子句平均长度、chronological 比例、每千冲突 restart 数；
  - 遥测 final 记录：负决策比例、原生建议为正的比例、target/saved/fallback 来源比例；
  - 最后一个检查点（≥ 1000 冲突才有）：glue 均值、低 glue 比例、stable 比例、trail 比例、saved 相位负比例、target 相位负比例；另加一个“有无检查点”指示。
- **缺失值**：树模型用固定哨兵 −10；逻辑回归用训练集中位数填补。

## 8. S2：候选选择器与冻结（≤ 12 个，预先列出）

| # | 输入 | 模型 |
| --- | --- | --- |
| 1 | 静态 | 成本树，深度 1（单阈值规则），叶子最少 20 个实例 |
| 2 | 静态 | 成本树，深度 3，叶子最少 15 个实例 |
| 3 | 静态 | 正则化多类逻辑回归（L2，C = 0.1，特征标准化） |
| 4–6 | 静态 + 试跑 b = 0.1 s | 同 1–3 |
| 7–9 | 静态 + 试跑 b = 0.5 s | 同 1–3 |
| 10–12 | 静态 + 试跑 b = 2 s | 同 1–3 |

- **成本树**：直接最小化训练集的总模拟 cost（第 4 节）。贪心二分，每个叶子选让叶内总 cost 最小的动作。阈值取特征取值的中点，最多 64 个分位候选；分裂必须让总 cost 严格下降。
- **逻辑回归**：标签为 best 动作。样本权重为 log2(m)，其中 m 是第 6 节的 margin；all-timeout 和 invalid 的实例权重为 0。预测时取得分最高的类。
- **选择规则**：在 dev（train + val）上做按家族组的 5 折交叉验证（seed 20261022，组按大小降序、以最大缺口规则分折），比较各候选的 out-of-fold 模拟 mean PAR2。
  - 静态候选（1–3）中取最低者，作为**静态选择器**；
  - 试跑候选（4–12）中取最低者，作为**试跑选择器**；
  - 平手时取更简单的模型（深度 1 < 深度 3 < 逻辑回归），再取更小的预算。
  - 辅助诊断：在 train 上拟合、在 val 上评估，以及按 split 和按年份的 CV 结果。
- **最佳固定动作**：dev 上 mean PAR2 最低的动作，只在 D/F+/F− 三者之中选。
- **冻结**：两个选择器在全部 dev 上重新拟合，导出为纯 JSON（`configs/three_way/frozen/`），与最佳固定动作一起提交，并打 tag `tw-freeze`，然后才运行任何 test 实例。冻结之后不再调参，也不更换主候选。即使 CV 显示选择器不如最佳固定动作，也照样冻结并在 test 上真实测试，如实报告负结果。

## 9. S3：真实测试与统计

- 在 99 个 test 实例上真实运行五个策略：D、F+、F−（`tw_test_fixed.json`），静态 wrapper，试跑 wrapper（`twrun.py wrap`）。所有策略同硬件、同内存、同证明政策。
- 主比较：两个 wrapper 分别相对**最佳固定动作**和相对 **D** 的配对 cost 差，即 mean PAR2 差和百分比。95% 置信区间用按家族组的 cluster bootstrap，10,000 次重采样，seed 20261022。
- 同时报告：solved 数、观察开销、各动作被选中的次数、选择错误的损失，以及 hindsight oracle（只作描述）。
- **严重回退**：wrapper 未解出而最佳固定动作解出；或者两者都解出，但 wrapper 的 cost 比最佳固定动作多出 2 倍以上且至少多 30 s。
- 分层报告：按配额年、按家族组、按规模层、按曝光（实例是否曾被运行、家族是否曾被运行），以及事后的 SAT/UNSAT。
- 只有一个 seed，这是局限。不追加 seed，也不挑选有利的 seed。
