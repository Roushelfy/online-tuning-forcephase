# 完成时间评价协议 v7

日期：2026-10-23（美东）。用户已明确将主指标改为“所有任务真正完成后的平均时间”。本协议定义新口径；[当前目标](AGENT_GOAL.md) 定义后续执行。v6 的冻结协议及 PAR2 结果继续保留为历史，不能重标为完整时间。

## 1. 指标与集合

设固定清单为 I，N = |I|。对方法 S，真实完成时间为 t(i,S)：

MeanCompletedCPU(S) = (1/N) × sum over i in I of t(i,S)。

单位为 CPU 秒，算术平均；同时报告总 CPU 秒及小时。节省百分比为 100 × (1 − mean(S)/mean(D))。运行中任何进程的 CPU 都计入，包含读取/扫描、观察、所有临时试跑、推理、算法重启、正式搜索与证明生成。独立答案检查的 CPU 另列，并计入研究账本。墙钟时间可作辅助指标，不能与 CPU 混用。

每个方法的 N 必须完全相同。任何实例未得到独立验证通过的答案时，该方法的完整均值和总完成耗时均为 null；其相对收益也不能用未完成的基线或策略计算。完成数、待完成清单与实际已消耗资源可以随时报告。

不使用超时惩罚、截断平均、成功题均值、按方法分别删除失败题、均值插补或模型预测来填补未知的完成时间。辅助分位数和中位数不替代算术平均。

## 3. 无评分截止与行政限制

新配置 scoring_cutoff_cpu_seconds 为 null，timeout_penalty 为 null。这表示主指标不截断，不表示关闭集群资源约束或承诺任何 SAT 实例都能在现有资源内完成。

正式运行入口必须支持持续搜索到答案；不得沿用 v6 的 remaining = 300 − observation 或其它隐藏评分截止。观察上限仍保留，失败时回退 D。固定二进制、seed、证明生成政策、CPU绑定和内存政策，记录节点及时间；正式策略保持独立的完整进程树计时。

调度抢占、配额、内存、墙钟或全项目 CPU 上限造成的中断是删失，不是 300/600 秒的完成。重启必须保存作废尝试及账本；没有真实状态快照，不能把两次从头搜索误称为接续。

累计预算仍为 200 CPU 核时。上一轮已用 144.65；每次调度前重新核账，并为独立验证和分析保留余量。资源不足时停止新作业并报告未完成，不能为得到有限分数改面板。

## 4. oracle 的确定与下界

对每题先找一个经验证的完整时间 b。只有对每个其它动作，都已有完整时间，或有有效未完成运行的实际 CPU 下界 ≥ b，才可确定该题的 oracle 时间是已完成动作中的最小值。

- 下界必须来自同一语义下实际执行且尚未完成的有效轨迹；不能使用请求的 time limit、PAR2、预测耗时、OOM 或错误记录。
- 已验证的完成时间和有效下界都有相同的二进制/seed/输入/证明与计时语义。
- 允许停止已经不可能更快的慢臂。这不会使慢臂自身成为“已完成”。
- 只有 N 题的最小值全部确定，才报告 oracle 的完整平均。若默认 D 仍未完成，其相对 D 的收益仍未知。
- oracle 的理想时间不包括为研究而跑三个臂的测量成本；研究测量 CPU 全部照常进入账本。实际部署策略若试跑多个臂则必须全部收费。

## 5. 记录 schema 与评价脚本

入口：scripts/completion_v7/evaluate.py（仅 Python 标准库），读取固定配置、固定面板和规范化运行记录 JSON 列表。每个“实例×方法”只能有一条按预定顺序选定的测量记录；全部历史尝试另存，不能按最快时间挑选。

每条记录包含：

| 字段 | 定义 |
| --- | --- |
| instance / method | 清单中的 hash / 配置中的方法标识 |
| status | solved、censored、noncompetitive_bound、running、error、missing |
| cpu_seconds | 原始计时得到的实际进程树CPU；未完成时只代表实际运行下界 |
| time_kind | 必须为 measured_process_tree_cpu，禁止 PAR2 / cost 惩罚列 |
| source_run_id | 可追溯原始记录的运行身份 |
| verified | 仅答案独立验证通过时为 true |
| measurement_valid | 配置、输入、计时语义及记录完整性通过核对时为 true |

censored / noncompetitive_bound 的有效 CPU 可用于 oracle 下界；running、error、missing 不用于认证最优。solved 只有 verified=true 且 measurement_valid=true 才是完整标签。已验证的解出发生在 600 秒以上也合法；数字 600 本身不是超时标记，状态与来源才决定含义。

示例命令（runs.json 由长时运行/复用审计入口生成，不是将旧成本列改名）：

```bash
python3 scripts/completion_v7/evaluate.py \
  --config configs/completion_v7/protocol.json \
  --runs "$FP_DATA/runs/completion_v7/normalized.json" \
  --out results/completion_v7/summary.json
```

未完成时仍写进度 JSON（mean/total/gain 为 null），并默认以退出码 2 阻止当作完整主结果；只生成进度时显式加 --allow-incomplete。缺失、重复、越界实例、负数、NaN / Infinity 及声明为惩罚来源的 CPU 都会被拒绝。脚本本身不运行求解器，也不授权额外资源。

检查命令：

```bash
python3 -m unittest discover -s tests -p test_completion_v7.py -v
```

## 6. 训练与结论

后续以真实完整时间、绝对秒数节省为优化目标。旧 300 秒解出概率 / 600 成本标签不能继续充当长时完成目标。未完成样本是删失信息；统计建模估计与实测完整均值分开，不能用估计值发布“全部算完”的成绩。

只有同面板的完整比较齐备后，才报告收益与家族聚类区间。当前 55 题已经曝光，其长时结果也不能改称独立盲测。历史 12.9% / 9.1% 是旧截断口径的参考，不是本协议下的已测收益。
