# v10 协议：跨规模的低成本 D / F+ / F− 三选一

日期：2026-10-26（UTC）。执行目标：[Agent Goal v10](AGENT_GOAL.md)。资源政策：[RESOURCE_POLICY.md](RESOURCE_POLICY.md)、[run_timeout_policy.json](../configs/run_timeout_policy.json)。机器配置：[protocol.json](../configs/cross_scale_v10/protocol.json)、[stage_plan.json](../configs/cross_scale_v10/stage_plan.json)。旧实验审计：[PRIOR_AUDIT.md](../reports/cross_scale_v10/PRIOR_AUDIT.md)。

本协议在任何 v10 新求解之前提交。冒烟测试只用了 3 道已曝光的 v9 题，不进入分析。之后的改动只追加到第 12 节。

## 0. 起点、曝光与固定项

- **曝光**：v9 及以前的全部数据（v9 开发、留出、外推、外部、原 55 题、v8 54 题）都已曝光，只用于开发、探索与单独标记的历史再评价，不再称为新盲测。本协议的候选规模就是参考 v9 的 D 成本确定的（第 3.2 节）。
- **求解器与动作不变**：CaDiCaL c607304（3.0.1），`build/fpc/cadical --lrat=1 <动作> --fpc=1`，seed 0，RLIMIT_AS 16000 MB。
  - D = `--phase=1 --forcephase=0`
  - F+ = `--phase=1 --forcephase=1`
  - F− = `--phase=0 --forcephase=1`
- **答案检查**：SAT 用 checkmodel，UNSAT 用 lrat-trim（64 GB）独立检查。检查失败不算已解，检查器 CPU 另列研究账本。
- **单次上限**：每题每方法完整进程树最多 3600 CPU s。在线方法的解析、静态分析、全部 probe、模型推理、停止 / 启动、重启与正式求解合计计时。项目与阶段累计核时不限。

## 1. 部署语义（wrapper，`scripts/cross_scale_v10/wrapper.py`）

1. **静态分析**（用到 A 特征的策略）：运行 `build/tools/static10`，图部分有工作量上限 5×10⁷ 次字面访问，整体 CPU 上限 2 s。超出上限或失败时，静态特征记为缺失。
2. **probe**：按策略列出的顺序，每个 probe 是该臂的正式命令，在原始输入上运行。
   - 窗口 τ 是 probe 进程自己的 CPU，从启动算起，含解析与预处理。到 τ 发 SIGTERM，1 s 后仍未退出则发 SIGKILL。
   - **任一 probe 在窗口内给出答案**（退出码 10 / 20），整个运行就以这个答案结束：答案经独立检查后返回，后续 probe 不再运行。
3. **全部 probe 未解**：每个 probe 的证明随即删除。特征只读该 probe 在停止前写出的内容：
   - CaDiCaL 收到 SIGTERM 时打印的统计块；
   - 遥测的 `final` 记录；
   - 进度行。

   然后按 `common.decide` 选一个动作，用 exec 把 wrapper 进程换成该动作的正式命令，从头运行。选 D 也重新收费，不续用 probe 进程，也不暂停后恢复。exec 前把内核 CPU 上限设为 3600 减去已用 CPU。
4. **在线输入**：只有 CNF 文件本身和上述 probe 输出。实例 ID、文件名、来源、生成 seed、类型名与答案都不作为在线输入。
5. **单线程串行**：所有 probe 依次运行，不用并行制造墙钟优势。

## 2. 状态

| 状态 | 含义 |
|---|---|
| `solved` | 答案经独立检查通过，且 CPU ≤ 3600 s |
| `policy_timeout` | 达到 3600 s 未给出答案，或越过上限才给出答案 |
| `unverified` | 给出答案但检查器失败（例如内存不足） |
| `censored` / `platform_disk` | 平台中断 |
| `error` | 其他失败 |

- 这些状态在报告中分开列出。旧的 300 s 证据不会自动变成新的超时。
- 平台中断与错误在新 stage 中从头补跑，保留原记录。

### 3.3 独立试采样（72 题）与调整规则

- **样本**：3 类型 × 4 档 × 6 题。seed = 10900000 + 1000·类型序号 + 100·档序号 + j，类型序号 rand3 0、col3 1、assign2 2，档序号 S 0、M 1、L 2、X 3。
- **只跑 D**：只核实生成是否正确、是否真的进入搜索，以及成本能否覆盖。不运行 F±，不看 F± 胜率、答案或收益。
- **统计量**：每档 6 题 D CPU 的几何平均 g。超过 3600 s 的按 3600 计下界。
- **开发档（S / M / L）**：
  - g 落在区间内就保留：S ∈ [0.05, 2] s，M ∈ [0.5, 20] s，L ∈ [2, 200] s。
  - 否则用该类型全部点（v9 每参数 ≥ 10 题的点，加 4 个试采样点）做 ln g 对规模参数的最小二乘直线，取预测 g 等于目标（S 0.3、M 3、L 30 s）的参数，并取最近的网格点。
- **外推档 X**：6 题 D 的最大 CPU ≤ 1200 s 就保留；否则在 (L, X) 之间取最大的网格点，没有就取 L 之上的第一个网格点。
- **约束**：必须严格满足 S < M < L < X，否则该类型保留候选值。
- **只调整一次**，不做第二轮试采样。结果写入 `scales.json`，与正式清单一起冻结。

### 3.4 正式面板

- **核心**：每类型每开发档 60 题，共 540 题。seed = 10000000 + 100000·类型序号 + 10000·档序号 + j。
- **划分**：格内按 sha256(ID + ':v10split') 排序，排名 0–29 为开发（270 题），30–59 为确认（270 题）。确认题固定分为三块：H1 排名 30–39、H2 40–49、H3 50–59，每块每格 10 题，共 90 题。
- **规模外推**：每类型在档 X 上 30 题，共 90 题，同一 seed 公式（档序号 3），不进入训练。
- **查重**：SHA-256、规范子句集哈希、换号不变哈希。v10 全部实例（试采样与正式）之间两两不同，并与 v8、v9 全部清单不同，结果写入 `results/cross_scale_v10/dedupe_audit.json`，有任何冲突就停止。
- **分组**：每个生成实例就是一个基础实例。稳健性诊断中的重排变体随其基础题分组，不算新样本。
- **冻结**：确认集、外推集与外部集在主策略冻结之前不生成任何运行或特征。冻结后不删除难题，也不按策略赢家挑题。

### 3.5 外部家族（120 题，规则见 [external_rule.json](../configs/cross_scale_v10/external_rule.json)）

- **来源**：SATLIB 公开基准，非比赛实例，16 个家族。核心训练的三类（随机 3-SAT、G(n, m) 三着色、耦合分配）以外的家族有 15 个：BMC、Beijing、准群、积木世界、汉诺塔、奇偶、鸽笼、全区间序列、归纳推理、ssa、bf、jnh、aim、dubois、pret。另有 4 道 DIMACS 大图 k 着色，标为“近核心”。
- **选题**：每个家族排除 v9 用过的文件，按子句数（再按自然文件名）排序，取均匀分位位置。
  - 与已曝光实例（v8、v9、v10 核心，以及 GBD 中文件名匹配这些家族的比赛 CNF）或更早选中的题重复时，用同家族的下一个未用文件替换；
  - 家族不足时如实报告短缺，不复制凑数。
- 选题不使用难度试采样。完整的难度分布在运行后如实报告，不期望全部是亚秒题。
- 外部结果与核心结果分开报告，不参与任何模型或阈值选择。

## 5. S2：选择空间与误选代价

在 v9 已有数据（开发、留出、外推；历史再评价，单独标明）与 v10 新开发集上报告：

- **固定模式**：各固定模式与开发 SBS 的差异。
- **单题风险**：逐题最大损失（相对 SBS 与 D）。
- **收益集中度**：前 1 / 3 / 10 题占比。
- **分层**：类型 × 规模。
- **事后标签**：
  - 明显优势：某动作相对另一个同时快 ≥ 20% 且 ≥ 1 s；
  - 接近：未达到明显优势；
  - 因超时未知：只在下界足够时才判已证实优势。

  这些标签只用于报告，不删题，也不作训练标签。
- **oracle**：事后最优，作参照，不可部署。有未知臂时报告可证明的界或 null，不把已完成臂的最小值当作精确 oracle。
- **稳定性**（`robust_dev`）：
  - seed 1 与重排变体下，赢家是否稳定；
  - 总收益是否稳定（F+、F− 相对 D）；
  - 严重损失是否稳定，即 SBS 相对 D 慢 ≥ 20% 且 ≥ 1 s 的题。

  重复不算独立样本。
- **SAT / UNSAT**：只作事后分析。

## 6. S3：三类观察与对照

### 6.1 登记特征（`scripts/cross_scale_v10/common.py`）

- **A 静态**（20 个，`tools/static10.c`）：

  | 类别 | 指标 |
  |---|---|
  | 规模 | 变量数对数、子句数对数、子句 / 变量比、平均子句长 |
  | 子句长度 | 二元比例、长度 ≥ 4 比例 |
  | 极性与形状 | 正文字比例、Horn 比例、反 Horn 比例、全负比例、全正比例 |
  | 变量出现次数 | 平均出现次数对数、出现次数变异系数、出现次数 ≤ 3 的比例、出现在二元子句中的变量比例 |
  | 变量极性 | 平均极性不平衡、单极性变量比例、短子句加权正向压力 |
  | 变量交互图 | 抽样 ≤ 256 个变量的平均度对数、局部聚类系数（有工作量上限） |

  不使用来源字符串。
- **B 默认前缀**：A 的 20 个，加 D 臂的 10 个前缀指标：
  - 冲突速率对数、决策 / 冲突、传播 / 决策对数、学习子句平均长度；
  - 最后进度行的 glue、trail 比例、剩余变量比例；
  - 后半窗口冲突增长 log₁₀((1 + 停止时冲突) / (1 + 停止时刻一半以前最后一行的冲突))；
  - 每千冲突重启数、负决策比例。
- **B_v9 旧基线**：v9 的 12 个内容门指标，取 D probe 停止前最后一个 checkpoint，固定不改。
- **C 三模式**：A 的 20 个 + D 臂 10 个 + F+、F− 臂各 9 个（不含负决策比例），再加 F+ − D、F− − D 在 7 个指标上的差（冲突速率、决策 / 冲突、传播 / 决策、学习长度、glue、trail、增长），共 62 个。

### 6.2 缺失

- 某个读出器需要的 probe 臂没有进入搜索（停止时冲突数为 0）：取 `missing_action`，即该策略的基线动作。
- 其他单项缺失（例如没有进度行，或静态分析触顶）：用训练折中位数填补。
- 归一化、填补与特征选择都只用训练折。缺失与触顶次数单独报告。

### 6.3 方法族与网格

| 族 | 观察 | 内层网格 |
|---|---|---|
| SBS | 无 | 固定动作 ∈ {D, F+, F−} |
| A | 静态分析 | 读出器网格（第 7.1 节） |
| N_B（无内容对照） | D probe τ，未解则固定后备 | τ ∈ {0.1, 0.5, 2, 5}，后备 ∈ {D, F+, F−} |
| B_v9（旧基线） | 同 N_B 的 probe + v9 的 12 个指标 | τ 与读出器网格 |
| B | 静态分析 + D probe τ | τ ∈ {0.1, 0.5, 2, 5} 与读出器网格 |
| N_C（无内容对照） | 三臂各 τ，未解则固定后备 | τ ∈ {0.1, 0.5, 2}，顺序 ∈ {D→F+→F−, F+→F−→D}，后备 ∈ {D, F+, F−} |
| C | 静态分析 + 三臂各 τ | τ、顺序与读出器网格 |

- **固定参照**：REF = D 2 s → F+，无论结果如何都报告。
- **另外报告**：固定 D、F+、F−，以及 oracle。
- **同成本对照**：N_C 与 C 的 probe 完全相同，N_B 与 B 的 probe 完全相同（B 另有静态分析，其成本照计）。所以“内容选择 − 无内容调度”的差，就是读出内容带来的增量。
- **收益分解**：每个族报告有多少收益来自 probe 提前解出、多少来自选择。

### 6.4 开发成本模型（离线模拟）

对开发题 i 和一个调度，全部用 `measure_dev` 与 `s1_dev` 的实测值计算：

- **观察开销**：
  - wrapper 启动 CPU（MEASURE 记录的 `own_cpu_at_start`）；
  - 用到静态分析时，加 static10 的 CPU 和 wrapper 在这一步自身的 CPU；
  - 按顺序加每个 probe 的 CPU 和 wrapper 在该 probe 上的 CPU。
- **probe 答出**：第一个答出的 probe 结束运行，成本就是到这里的累计开销，算已解。答案须与固定运行的已验证答案一致，否则按错误处理。
- **全部未解**：成本 = 开销 + t_a(i)，t_a 是 s1_dev 中所选动作的完整固定运行 CPU（同一命令、同一搜索）。
  - 固定运行已解且总成本 ≤ 3600 s，才算已解；
  - 否则为超时，资源成本记为 3600 s。
- **校验**：这个拼接只用来筛选。冻结后，主策略与参照的真实 wrapper 也在开发集上运行（`deploy_dev`），报告模拟与实测的差距。最终结论只来自冻结后的真实部署。

## 7. S4：读出器、分组验证与冻结

### 7.1 读出器（只有两种）

- **基线动作 b**：在训练折中、该调度的 probe 都未解出的题上，按第 7.3 节准则最好的固定动作。读出器只决定是否偏离 b。
- **岭回归动作成本差模型**：
  - 对每个 a ≠ b，在训练折未解题上回归 Δ_a = t_a − t_b（秒），α ∈ {0.1, 1, 10}，特征先填补再按训练均值 / 标准差标准化。
  - 超时标签按右删失处理，只用有证据的方向：
    - a 超时、b 已解：Δ_a 取下界 3600 − t_b；
    - b 超时、a 已解：Δ_a 取上界 t_a − 3600；
    - 两者都超时：Δ_a = 0。

    这样两种情形都偏向保守，不把 3600 当完成值。
  - 预测最小的动作，其 ŷ < −θ（θ ∈ {0, 0.1, 1} s）时才偏离 b。
- **浅树**：
  - 深度 2 或 3，候选阈值取训练折的 25 / 50 / 75% 分位，叶最少 5 题；贪心选使叶成本总和最小的分割，只在严格变小时才分割。
  - 叶内动作按第 7.3 节准则选（先解题数，再总 CPU）。偏离 b 的条件：叶内总节省 > θ × 叶大小，且解题数不少于 b。

### 7.2 嵌套分组验证

- **外层**：5 折，折号 = 格内分割排名 mod 5，每折每格 6 题。
- **内层**：3 折，折号 = 训练集内格内排名 mod 3。
- **只在训练部分做的选择**：τ、顺序、读出器、α / 深度、θ、填补值、基线动作，以及 SBS 本身。
- **各族的估计**：外层逐题成本之和（OOF）。
- **留一规模档诊断**：在两个开发档上训练（含内层选择），在第三档上评估，与同样两档选出的 SBS 比较。这只是开发诊断，不是独立外推成功。
- **代理审计**：报告 A_s（只用 5 个规模 / 形状指标：变量数、子句数、比值、平均长度、二元比例）的 OOF，以及读出器决策在类型 × 档格内的一致度，检查模型是否只学到规模 / 类型代理。A_s 不作主策略候选。

### 7.3 统一选择准则（内层选择、SBS 与主策略都用）

1. 已解题数多者优先；
2. 其次总方法 CPU 低者优先。有超时时，它只称“有限截止下的资源成本”，不称完整平均完成时间。

**并列**：已解数相同、总量相差在 1% 以内时，依次优先：

1. 平均观察开销低的；
2. 复杂度低的，顺序为 SBS < A < N_B < B < N_C < C；网格内：岭回归先于树，α 大者先，深度小者先，θ 大者先。

### 7.4 主策略规则

1. **候选**：SBS、A、N_B、B、N_C、C。B_v9 与 A_s 只报告，不作候选。
2. **逐级比较**：现任从 SBS 开始，按复杂度顺序逐个比较。后者“胜过”现任的条件：OOF 已解数更多，或已解数相同且 OOF 总量 ≤ 0.99 × 现任总量。胜过就成为现任。
3. **内容族的附加条件**：内容族（A、B、C）还必须以同样的标准胜过自己的同成本无内容对照（A 对 SBS，B 对 N_B，C 对 N_C），否则不能成为现任。
4. **主策略**：最后的现任。
5. **报告**：B 相对 A、C 相对 B、C 相对 N_C、B 相对 N_B、A 相对 SBS、B 相对 B_v9 的 OOF 差，用格内分层配对 bootstrap（10000 次，seed 0）给出 95% 区间。

### 7.5 冻结

- **拟合**：主策略的族在全部 270 道开发题上，用内层 3 折选配置，再在全部开发题上拟合，写成 `configs/cross_scale_v10/frozen/main.json`。
- **至多一个固定参照**：
  - 主策略是内容族时，参照就是它的同成本无内容对照：τ / 顺序相同，后备在全部开发题上选；主策略是 A 时，对照即 SBS（固定动作已在每题运行），参照改为 REF。
  - 主策略是 SBS、N_B 或 N_C 时，参照为 REF（D 2 s → F+）；若主策略恰好就是 REF，则不另设参照。
- **全部在 H1 之前冻结**：缩放、特征、模型、阈值、SBS、参照与运行计划，提交并打标签 `v10-rule-freeze`。
- **负结果**：没有增量时冻结 SBS 作为负结果，不强迫选复杂模型。

### 8.2 统计

- **全部方法都完整完成的面板**：报告同一固定面板的算术平均 CPU、总 CPU，以及相对 D 与开发 SBS 的收益 = 1 − 均值 / 对照均值。
  - **区间**：格内分层、按实例配对的 bootstrap，10000 次，seed 0，95% 分位区间。确认集按 9 格分层，外推按类型，外部按家族组。
- **有超时的面板**：完整均值与相应收益为 null。报告：
  - 3600 s 内已解数，分 SAT / UNSAT；
  - 配对新增 / 丢失的题；
  - 预定时间点 1 / 10 / 60 / 600 / 3600 s 的解题数与解题曲线；
  - 逐题删失状态。

  不同的已解数用配对分析与区间，不凭一题之差宣称可靠胜利。共同完成子集的均值只作次要描述，并标明筛选偏差。不用 PAR2，不把 3600 当完成时间，不删最慢题。
- **还要报告**：
  - 观察开销的平均与分位数；
  - 赢家分类（仅作辅助）；
  - 最大误选损失；
  - 前 1 / 3 / 10 个收益占比；
  - 类型 / 规模分层、H1 / H2 / H3 分块、事后答案分层；
  - 收益中来自 probe 提前解出的部分。

### 8.3 判定

- **实际价值**：同范围确认 270 题上，主策略相对开发 SBS 的平均 CPU 至少减少 5%，且配对 95% 区间下界 > 0。
- **内容选择的收益**：主策略为内容族时，相对其同成本无内容对照的区间下界也须 > 0，否则只能称预求解 / 调度收益。
- **跨规模**：同范围获益不能称跨规模成功。外推单独呈现相对 D 与 SBS 的方向、区间与集中退化。某类型若有可靠的严重退化，明确限制适用范围。
- **外部家族**：结论单独列出。
- **不回调**：不看确认结果回头调模型。新假说用新的独立确认集，标为下一轮。
