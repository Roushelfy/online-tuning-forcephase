# 当前科研资源政策：不设核时限制

生效日期：2026-10-24（美东）。来源是用户直接指令：

> 删掉这个限制，没有核时限制。重新规划下阶段目标

## 权限与适用范围

从本指令起，**没有项目累计、阶段累计或普通正式求解的CPU核时硬上限**。旧200核时、各阶段40/10/4.11/2.26核时以及由它们推导出的“剩余预算”全部失效；不能因账本越过旧数字而停止、缩减正式样本、跳过必要实验，或重复请求同一授权。

权威机器配置：[configs/resource_policy.json](../configs/resource_policy.json)。它优先于本仓库历史目标、协议、计划中的核时预算。历史预算来自此前的研究规划，不是用户要求，也不是已核实的集群配额。

这项更正不删除科研账本：求解、生成、特征、验证、失败和重跑继续如实计量。197.74核时是截至v8的历史累计，不是距离停止阈值的余额。

## 运行器的当前语义

- v7 longrun 与 v8 runner 已接入当前政策。旧 --budget-cpu-hours 参数为命令兼容保留，但忽略，不再触发停止；省略该参数也可以。
- 普通作业的旧 cap_cpu 不再限制正式完成。只有明确声明的 observation_window 或 oracle_noncompetitive_bound 保留有限算法窗口；前者是短试跑方法的一部分，后者是已知更快解之后的最优性取证，不是资源配额。
- v7 oracle规划器不再按阶段核时预算遗漏候选，默认写新的 stage2_unlimited.json，不覆盖历史stage2计划。
- 新运行加入资源政策身份，避免与旧截止语义的运行混淆；控制器写出effective_plan.json，后续归一化应读取实际有效计划。新计划生成器也应先应用当前政策再冻结。未声明新政策的历史run_id算法保持不变，旧记录仍可被历史归一化脚本找到。
- 新阶段使用独立stage名与配置。旧的已停止记录只是删失，不能让“文件存在”变成该题已完成；需要补跑的记录创建新stage并按预定采用规则合并。
- Slurm启动脚本不再传入核时停止参数。作业墙钟、并发、内存和证明存储根据真实平台情况安排；实际调度限制引起中断时保存进度并安排后续工作，不转化成评分截止，也不重新引入累计核时配额。

## 科学边界

仍然固定清单、保留完整时间主指标、独立验证答案、记录所有尝试。不因取消资源上限而无限调参或按结果挑数据。工作顺序由研究目标、实验信息价值和平台可用性决定，完成条件由科学问题决定。

观察预算τ仍然需要：研究任务本来就要求用低成本观察选择flag，τ是被比较的算法参数，不是实验算力上限。正式求解不以τ、300或600秒截断计分。

历史报告和冻结协议中的数值保持原样，以说明当时为何停止。它们不再是当前执行指令；复现旧版本行为时使用原commit/tag，不把旧预算重新作为现行政策。
