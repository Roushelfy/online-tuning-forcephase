## 1. 三类问题（[generators.json](../configs/stratified_v8/generators.json)）

每类只有一个规模参数，其余结构参数事先固定，不随试采样结果改变。

| 类型 | 生成 | 规模参数与候选网格 | 固定结构 |
|---|---|---|---|
| `rand3` 随机 3-SAT | `cnfgen -q --seed S randkcnf 3 n m` | n ∈ {150, 160, …, 450} | m = round(4.26 n)，即阈值附近；文字符号均匀（正负各半，作为方向对照） |
| `col3` 图 3 着色 | `generate.py` 用 random.Random(S) 均匀抽取 G(n, m)，存为 DIMACS 图文件，再由 `cnfgen -q kcolor 3 dimacs <图>` 编码（实测 CNFgen 的 `gnm` 在 `--seed` 生效前就已建图，不可复现） | n ∈ {100, 125, …, 400, 450, …, 700, 800, 900, 1000} | 随机图 G(n, m)，m = round(2.3 n)，平均度 4.6，接近 3 着色阈值；每点至少一色、两两至多一色、每边每色一个二元子句 |
| `assign` 耦合任务分配 | `scripts/stratified_v8/generate.py`（PySAT CardEnc，顺序计数器编码） | T ∈ {40, 60, 80, 100, 125, 150, 175, 200, 250, 300, 350, 400, 500, 600} | 4 个资源；每个任务随机允许其中 3 个；每任务恰选一个（CardEnc.equals）；每资源至多 ceil(1.04 T / 4) 个任务（CardEnc.atmost）；冲突图 G(T, round(2.8 T))，冲突任务不得共用资源 |

- `assign` 的三类约束相互耦合：恰一、容量、冲突。主实验只用顺序计数器一种编码；其他编码、换号和重排都不做（预算不足）。
- CNF 不带注释写入 `$FP_DATA/stratified_v8/cnf/<id>.cnf`。清单记录命令、参数、seed、生成器版本、文件 SHA-256、与子句顺序无关的规范哈希（查重用），以及变量、子句、单元、二元子句数和生成 CPU。重复生成必须得到相同的 SHA-256。同构查重只做到规范哈希这一层。
- 生成 seed 与 solver seed（恒为 0）分开记录。实例 ID 含类型与规模，但 ID、类型标签、seed、真实 SAT/UNSAT 都不作为部署输入；部署只读 CNF。

## 2. 试采样与尺度校准

- **第 1 轮**：3 类型 × 3 档，每格 1 题。初始参数：
  - `rand3`：S 260、M 300、L 340；
  - `col3`：S 250、M 400、L 550；
  - `assign`：S 100、M 200、L 300。

  seed = 8000000 + 1000·轮次 + 100·类型序号 + 10·规模序号，类型序号依 rand3、col3、assign，规模序号依 S、M、L。
- 每题跑 D、F+、F−，第 1 轮另把 D 重复一次，用于计时噪声。单次行政上限 180 CPU 秒；第 1 轮总预算 0.35 核时，生成与两轮试采样合计 ≤ 0.75 核时。被停止的运行照样记录为未完成。
- **成本统计**：c = D、F+、F− 三次 CPU 的平均。被停止的运行以实际 CPU 计入，作为下界。
- **目标与区间**：S 2 s ∈ [1, 5]，M 10 s ∈ [5, 30]，L 40 s ∈ [30, 120]。选区间内偏下的目标是为了算力。只按完成成本、是否进入搜索和覆盖来选，从不看哪个动作赢。
- **第 2 轮**：只为第 1 轮 c 落在区间外的格补题，每格 1 题，用新 seed。参数按下面的规则在网格上选：
  1. 用该类型第 1 轮三个点做 log c 对网格序号的最小二乘斜率 s；
  2. 从同格的第 1 轮点外推：g* = g + (log 目标 − log c)/s，取整后截到网格内；
  3. 若 s < 0.05，或 g* 与原点相同，则朝需要的方向移动 3 格；
  4. 同类型 S < M < L 必须严格递增，冲突时朝各自区间方向错开一格。
- **最终尺度**：在该类型所有已测点（两轮都算）中，选 c 落在本格区间内、且 |log c − log 目标| 最小的点。若没有，则用该类型所有已完成点重新拟合斜率，从最近的已测点外推到网格上。仍须严格递增。
- **计时噪声与“明确优势”阈值**：r = 第 1 轮中均值 ≥ 0.5 s 的 D 重复对的 |t1 − t2| / 均值 的中位数。τ_rel = max(0.05, 3r)，τ_abs = 0.25 s。动作 a 相对 b 有明确优势，当且仅当 t_b − t_a ≥ max(τ_abs, τ_rel · t_b)；否则记为接近。原始秒差与比值都保留。

## 3. 正式面板规模 N 的选择规则（在试采样前写定）

- Ĉ_c：格 c 所选参数下每题三个动作 CPU 之和的估计。取该参数下已测试采样题的实测值（被停止的按下界）；没有实测则取 3 · exp(预测 log c)。
- κ = 1 + 试采样检查器 CPU / 试采样求解 CPU；长尾系数 K = 2。
- 留出题还要多跑一次 wrapper，约等于三动作成本的 1/3。成本估计为：

  cost(N) = K · κ · Σ_c Ĉ_c · (n_dev + n_hold · 4/3) + 0.2 s · N

  其中 (n_dev, n_hold) 为每格的开发 / 留出题数：90 → (7, 3)，54 → (4, 2)，27 → (2, 1)。
- 可用正式预算 B_f = 200 − 试采样结束时的账本 − 0.35（建模、分析、报告）− 0.26（预留）。检查器 CPU 已由 κ 计入正式预算。
- 取 {90, 54, 27} 中 cost(N) ≤ B_f 的最大 N。都不满足时，只交付试采样与资源缺口。
- 局限：每格只有 1–2 道试采样题，不能保证正式题全部完成。报告会保留这一点。

## 4. 正式面板冻结

- 每格 n_dev + n_hold 题，seed = 8100000 + 10000·类型序号 + 1000·规模序号 + j，与试采样 seed 不相交。基础实例 ID 为 `v8-<类型>-<规模>-<jj>`。
- **分割**：格内按 sha256(ID + ':v8split') 排序，前 n_dev 个为开发。只用生成身份，在任何正式运行之前确定。
- 冻结内容：清单（命令、seed、参数、SHA-256、规范哈希，查重须通过）、`panel_dev.txt` / `panel_holdout.txt`、评价配置与账本。冻结提交之后，不再因难题、超时或不利赢家改 N、换题或删格。

## 5. 运行（`scripts/stratified_v8/runner.py`、`slurm_run.sh`）

- 一个 cpu-low 节点上非独占地申请 72 个逻辑 CPU（36 个物理核）、700 GB 内存。K = 物理核 − 4 个运行位，每个运行绑定一个物理核；控制器与检查器使用其余的核。
- 队列顺序事先固定：先 L，再 M，再 S；同一规模内依 rand3、col3、assign；格内按分割哈希；同一题的各动作相邻。
- **行政停止**：
  - 单次上限：试采样 180 s，正式 900 s。到达即停止，记为 censored。
  - 阶段预算：所有运行累计 CPU 达到预算时，停止正在运行的（censored），未启动的记为 not_started。
  - 两者都只是资源保护，不是评分截止；被停止的运行没有完成时间，相关均值为 null。
- **S1**：只跑开发题的 D、F+、F−，预算 B_S1 = B_f − K·κ·Σ_c Ĉ_c·n_hold·4/3。留出题在规则冻结之前不生成运行，也不计算特征。
- **S3**：规则冻结并提交之后，在同一批次中交错运行留出题的 D、F+、F− 和 wrapper W（若有冻结策略）。预算 = 200 − 当时账本 − 0.30。

## 6. S1 基线分析（BASELINES.md）

- 按类型、规模、实际难度，给出三个动作的完整平均（全部完成才给）、逐题时间比、赢家分布（明确优势 / 接近）和收益集中度。
- 另报：预处理直接解出（冲突数为 0）的比例、观察开销前已结束的题、接近组和 D 优势题。
- SBS = 开发集上总 CPU 最小的固定动作。若某动作有未完成的开发题，它的总量只有下界：若下界已大于已完成动作中的最小总量，则排除；否则 SBS 记为“未定”，并在已完成的动作中选。
- oracle 用 v7 的确定规则：某动作的完成时间 ≤ 其他动作的完成时间或实际下界。
- **跳过规则**：若 Σ_dev(t_SBS − t_oracle) ≤ 2 · Σ_dev 观察成本，则不训练选择器，记为“未开展选择器研究”。

## 7. S2 特征与两种小方法（FEATURES_AND_RULES.md）

- **观察**：`build/tools/obsprofile6`（v6 工具），sections s28、polar、resid、bilat，v6 的分节上限，总上限 2 s，seed 20261023。观察失败或未完成时取 D。观察成本 = 实测 obsprofile6 CPU + 0.05 s wrapper 开销（用于交叉验证；留出集上用 wrapper 的真实进程树计时）。
- **11 个指标**：
  - 规模（只用规模的对照组）：p_log_vars、p_log_clauses、p_cv_ratio；
  - 结构与方向：a01_wpos_frac（加权正文字比例）、p_bin_frac、p_allpos_cls_frac、p_allneg_cls_frac、a04_viol_w_lr（全假与全真赋值违反权重的对数比）、b03_props_lr_mean（正向与负向决策的传播量对数比）、b07_confdepth_pos_log2、b07_confdepth_neg_log2（全真与全假决策序列到冲突的深度）。
- **方法 T，浅规则树**：深度 ≤ 2；分裂取 11 个指标在训练折上的 25/50/75% 分位。叶内选总 CPU 最小的动作，但只有叶内 ≥ 3 题、且相对 D 的节省超过边际 θ_T ∈ {0, 2, 10, 30} s 时才偏离 D。穷举搜索，目标为训练集总 CPU（含观察成本）。
- **方法 R，岭回归**：对 a ∈ {F+, F−} 回归 y_a = t_a − t_D（秒），特征按训练折标准化，α ∈ {0.1, 1, 10, 100}。取预测差最小的动作 a*，只有 ŷ_{a*} < −θ_R（θ_R ∈ {0, 1, 5, 20} s）时偏离 D。
- **交叉验证**：外层 6 折、内层 5 折，格内按分割哈希排名，折号 = 排名 mod K。内层选超参数，外层给出估计，目标为总 CPU + 观察成本。未完成的开发运行以下界参与训练和评价，并标注。
- **对照**：同样两种方法只用 3 个规模指标（T_s、R_s）。只有完整指标在同一读出器下更好，才说新增观测有用。
- **冻结规则**：在 T 与 R（完整指标）中取外层 CV 总量较小者；只有它小于 SBS 在开发集上的总量（SBS 是样本内选出的，这一比较偏向 SBS），才在全部开发题上重新选超参数并拟合、冻结。否则不冻结策略，S3 只跑固定动作。最多冻结 1 个策略。

## 8. S3 留出验证（VALIDATION.md）

- wrapper：观察 → 冻结模型选一次动作 → exec 进正式求解。全部进程树 CPU 计入，独立验证通过才算完成。
- 主比较：整个留出集上的完整算术平均与总 CPU。比较对象：D、F+、F−、SBS（开发集选定的动作）、oracle 和 W，同时报告相对 D 与相对 SBS 的收益。只要有题未完成，相关均值与收益为 null，并列出缺口。
- 区间：按格内配对 bootstrap（10000 次，seed 0，95% 分位区间）。只有 3 个生成类型，不能声称跨家族泛化。还要报告逐题正负收益、错误偏离与观察成本。
- 不依赖留出结果回调模型。

## 9. 偏离记录

1. **第 2 轮冲突处理的实现改为与第 2 节文字一致**（看过第 1 轮成本、尚未生成第 2 轮题时）：
   - 原因：第 2 节规定冲突时“朝各自区间方向错开一格”。原实现总把较高档往上推，会让 col3 的 L 档回到第 1 轮已超出区间的 n = 550，违背 L 应该变易的方向。
   - 处理：`enforce_order` 改为记录每档需要的方向（+1 变难，−1 变易，0 已在区间）。冲突时由较低档让到较高档下一格；只有较高档已在区间、两档都需要变易、或较低档已到网格底端时，才把较高档推到较低档上一格。
   - 结果：col3 的第 2 轮点为 375 / 450 / 500，而不是 375 / 500 / 550。
   - 第 1 轮结果（只看成本，赢家不参与规则）：rand3 的 S、M 在区间内；col3 很陡，n = 250 时 0.02 s，n = 400 时 1.3 s，n = 550 时超过 168 s；assign 在 T ≤ 300 时都在 0.1 s 内完成，只有 26–235 个冲突。assign 的外推全部截到网格上限，所以第 2 轮测 400 / 500 / 600；预计这一类在预注册的结构下达不到目标难度，作为“极快题”对照保留，不改结构参数。
2. **最终尺度：目标落在两个已测点之间时插值，不越过已测点外推**（看过第 2 轮成本、冻结正式面板之前）：
   - 原因：第 2 节写的是“从最近的已测点外推”。按原实现，rand3 的 L 档会从 n = 340（22.6 s，SAT 题）用斜率外推到 n = 360，但 n = 360 已实测三个动作都超过 180 s，高于 L 区间。选一个已实测超出区间的点，违背“按完成成本选尺度”的本意。
   - 处理：若某档在网格上被一个区间下方的已测点和一个区间上方的已测点夹住，就在两者之间按 log c 线性插值，取严格居中的网格点。两点相邻时，取 |log c − log 目标| 较小者，再按顺序规则错开。没有夹住时，仍按原规则外推。只用成本，赢家不参与。
   - 结果：
     - rand3 L 由 360 变为 350（插值估计每个动作约 64 s）；
     - col3 L 由夹住的 500 / 550 中取 500，因为 M 已在区间内固定为 500，按顺序规则为 550；
     - assign 没有区间上方的点，仍外推到网格上限，为 400 / 500 / 600。
   - 影响：这一改动改变了 N。按原实现，rand3 L 取 360、Ĉ 取实测下界 541 s，cost(54) = 4.19 > B_f = 3.09，于是 N = 27；按本偏离，cost(54) = 2.89 ≤ 3.09，N = 54。报告中会同时说明。
   - 第 2 轮成本：rand3 n = 360 三个动作都在 180 s 停止；col3 n = 375 / 450 为 SAT，0.26 / 0.35 s，n = 500 为 UNSAT，9.6 s；assign T = 400 / 500 / 600 只需 0.2–0.5 s。
   - 试采样合计 16 题（上限 18），求解 0.387 核时、检查 0.003 核时、生成 0.0008 核时，含烟雾测试后的账本为 196.30。
3. **交叉验证的折号按原文执行，空折跳过**（说明，不改规则）：N = 54 时每格只有 4 道开发题，“格内排名 mod K”使外层 6 折中只有 4 折非空、内层 5 折中只有 3 折非空，所以实际是外层 4 折、内层 3 折，每折每格各 1 题。
