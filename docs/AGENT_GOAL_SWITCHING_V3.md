## 4. P1：审计现有有限 oracle，分开初始选择与切换收益

复用严格门禁认可的旧开发记录；不对旧 test/t2026 做候选选择。重建每条完整可执行策略的终端成本，在**相同实例全集**上至少分别报告：

- 静态 SBS：预先选定的 I−，另列 D、F−；若另选 stage2-SBS，必须只用开发数据并在新测试前冻结。
- 静态 oracle：每实例事后在 {D, I−, F−} 中取最低成本。
- 固定 I− prefix 的一次切换 oracle：keep 与各已评估 I−→F− 时机取最低成本。
- 固定 F− prefix 的反向一次切换 oracle：keep 与各已评估返回动作/时机取最低成本；返回 D 和返回 I−分开列出。
- 全部已评估完整策略的有限 oracle；同时报告它相对静态 SBS、相对静态 oracle 的额外收益。不得把事后选择初始动作的收益全算成在线切换收益。

**定义与计分**：对样本 i、seed s 和完整策略 π，若总 CPU 时间 t≤T=300 s 且独立验证通过，则 L(i,s,π)=t；未解超时为 2T=600。有限 oracle 是预先列出的集合 Π 内的 `minπ L(i,s,π)`。配置的 prefix、特征计算、实际动作、continuation、证明生成均计入该次完整运行；checker CPU 另列并记总账。oracle 使用未来结果，只界定此候选集合的事后选择空间，不是任意在线策略的全局上界。

所有例子包括早解、未到检查点和超时；不只在“有决策点”子集上宣称总体提速。双超时说明当前 PAR2 无差异，不能推断真实完成时间或两个动作同样好。缺 replay/损坏遥测是错误，不是零收益标签，禁止用 baseline 回填。沿用严格、有限的异常分类，给出精确分母。

报告家族贡献、胜负集中度、leave-one-family-out 敏感性与 paired family bootstrap；旧记录仅一个 seed 的限制必须注明。新重复数据同时报告“逐 seed 事后选最佳”和“先对 seeds 求均值再选同一策略”，量化噪声与事后取最小值的乐观性；不能把多 seeds 当独立实例扩充显著性。

生成 `reports/stage2/HEADROOM.md` 和逐实例可追溯 CSV，解释旧约 4.8%/9% 的准确候选范围与分母。不要只重复旧百分比。若发现旧 oracle 无效，先纠正、披露再继续。

**P1→P2 门槛**：只依据旧 dev 的有限动态 oracle 相对 I−。若点估计 <3% 且 95% 区间上界 <5%，本轮不启动全集式补采/学习，完成“当前候选收益空间有限”的报告；不能写“所有在线切换无效”。其他情况可进入下面唯一固定的小规模补采，以区分存在收益与统计不确定性。区间宽不是无收益的证据。

## 5. P2：重新采集正确观测与反事实 continuation

### 5.1 数据与固定主矩阵

从原 train+val 的 **817 个实例、89 个家族组**中，按固定 seed `20261019` 预选 96 个 dev 实例，覆盖至少 20 个家族组。抽样依据仅限家族与旧 D 的运行难度分层；先保证家族覆盖，再在家族内分层，不按 F− 胜负、oracle gain 或 flip 取值选样。提交抽样算法、名单、hash 和抽中概率；报告仅针对该面板，不冒称代表全竞赛总体。若个别样本确实不可获取，在任何新结果出现前固定替补规则与名单。

scramble seeds 固定为 0/1，沿用保持极性的变量/子句/文字置换定义，不以 solver `--seed` 充当独立重复。K 固定为 {1e3,1e4,1e5} 冲突之后第一个自然 restart。主轨道是 C，固定 phase=0 的 I−↔F− 用于避免把初始正/负一起改变；D 与旧冻结调度保留作参照。

每个实例/seed 的 10 个完整配置：I− keep；I−→F−@三个 K；F− keep；F−→I−@三个 K；D keep；旧固定 F−→D@1e4。共最多 1,920 次运行。每条从原 CNF 开始，总预算始终 300 CPU 秒，统一 LRAT/模型验证政策与内存上限。新数据全部为同一 v2/schema；旧 v1 成本可作历史比较，不能与 v2 特征/标签拼成一套监督数据。

### 5.2 同起点重放与预算语义

优先复用现有确定性 replay，不为本轮另造 fork/COW 基础设施。比较保持/切换分支时，起点、完整已执行动作历史、构建、实例/置换、选项、遥测配置与随机流必须一致，直到目标动作之前。核对 pre-action digest、搜索计数、checkpoint、实际切换与动作方向；摘要只覆盖部分状态，报告称“检查到的 prefix 轨迹一致”，不能声称证明全内存逐位相同。

prefix 不能免费：禁止到检查点后再给 300 秒。若以后确实实现进程 fork，要在协议增补中处理累计 prefix CPU、剩余 `T−prefix`、proof 文件/ID、随机状态、资源计量与验证，先做一致性检查再纳入正式分数。

在 K 前解出时，该配置仍计入全体部署得分，保留已解成本；未到 K、无自然 restart、被预算终止、合法删失和数据损坏分别列出。证据不足的配对不得当训练标签；完整计划记录不能静默消失。

### 5.3 真正新增的观测与可学习性

所有特征必须在动作之前得到，保持固定大小采样。预先列出最多四组：

1. 静态 C；
2. C+进度/机制 R（CPU、冲突、stable、当前动作、驻留、rephase 状态）；
3. C+R+正确的极性统计（修复后的 saved flip、native/forced 方向分歧、saved/target 使用情况、缺失与 compaction 标记）；
4. 全部上述特征加短/长窗口趋势（如 glue、传播/决策、冲突进展的变化），窗口定义运行前固定。

checkpoint/window 分别维护同类历史；compaction 后样本重建、历史失效、无可比 flip 为 null。对相同 v2 数据做含/不含正确 flip 的消融，才有资格评价该特征的预测价值。不得补造旧 flip、使用终局答案、剩余真实求解时间、未来窗口、家族名/实例 ID 或轨迹之后的信息作输入。

先比较成本敏感简单规则、深度≤3树、正则 logistic；至多 12 个预先列明的超参数组合/选择问题，不进行无限搜索，不默认启动 RL/bandit。外层按 family group 固定 5 折，内层分组选择；同实例全部 seeds、所有检查点及路径属于同一折。缺失填充、缩放、选特征只在训练折拟合。主结果为未见家族 OOF；如另做同族新实例预测，单独按实例分折、全部 seeds 同折，并明确是较弱泛化目标。

比较 I−、D、F−、固定调度、静态选择器、时间/进度规则、内容观测模型与 shuffled-label 对照。以完整 PAR2 与 solved 为主，AUC/相关性只作诊断；同时给出相对 oracle 可利用收益捕获比例和错误切换损失。标签可按已观测 PAR2 差加权；双超时零终端差不当成已知真正偏好。

### 5.4 是否启动有限多次切换

最多两次切换是条件式扩展，不因上一轮一次选择失败直接否定，也不无条件实现复杂控制器。仅当 P1/P2 指出实质收益或动作偏好随阶段改变，而且预算预留仍充分时启动。启动前提交固定名单和配置，不能按新候选收益选实例。

从上述 96 例中用固定、独立于动作收益的规则预选 32 例、2 seeds，起始 I−，三个相同检查点各选择 keep/toggle，限制总切换次数≤2。完整枚举恰好 7 条动作序列（排除三次都切换）；最多 448 次完整运行，最坏 37.34 solver h。相同内容寻址的已存在路径可复用，不能借此漏计失败尝试。

第二次动作必须从**包含第一次动作的完整历史**重放。禁止把 I− 原生轨迹不同 K 的偏好或窗口成本拼接成多次切换结果；七条真实路径的 oracle 仍只代表这七条路径。若学习重复策略，固定最多两次、最短驻留与 enter/exit 迟滞；只在实际可达状态上决策，不加入额外 restart，沿用并披露 rephase 自然恢复与 trail reuse 语义。最多两次切换也不能概括任意重复切换。

**P2 交付**：完整 run manifest、严格覆盖审计、所有有效/无决策/删失/错误分母、v2 特征校验、有限 oracle 分解、OOF 全表/区间/消融与可选路径报告。oracle 收益小、策略学不出来、家族迁移失败、统计不确定，必须分别报告。

## 6. P3：把候选真正部署，确认不是离线评分假象

进入候选确认的门槛：在固定 family OOF 上，一个在线候选相对 I−及最强“不使用在线内容特征”的基线均降低 PAR2 至少 2%，且相应配对 family bootstrap 95% 区间下界>0。比较对象和并列规则提前固定；不能从几十个表挑一个未经选择修正的赢家。未过门槛则停止该分支，保留有限收益空间与不确定性的答案，不强行进入旧 test 挑选。

冻结一个主要在线候选算法与一个最强非内容基线，在 96 dev × 2 seeds 上实际运行（最多两策略，32 solver h）。这里使用 P2 外层验证的逐折冻结模型：每个实例由未训练过其家族的模型控制，同实例全部 seeds 使用同一外折模型。不能把全 dev 拟合的单模型跑回这 96 例，并据此声称实测支持 OOF 收益。动态路径没有完整反事实覆盖时，禁止用静态 replay 表假装得到其准确部署成本；须实际执行后才能进入确认。P3 通过后才用全部 dev 重训最终模型，冻结后仅用于 P4；训练集回测只可标为诊断。

检查导出模型与 Python 的预处理、缺失、分数和动作一致性；检查的必须是本次模型/hash。CPU 作为输入时单列计时敏感性。实际 prefix、切换时刻、驻留、最多次数、路径外状态均留痕。离线与实测不一致先诊断，不用测试集选择补丁。

用预选的 16 个 dev 实例、{patched-off, telemetry-only, deployed}、各3次，在同核低并发、平衡随机顺序下测 v2 额外开销（最坏12 solver h，计入预留）。目标中位≤1%、p95≤3%；给出噪声/区间与不对称超时。实际部署终端时间已包含开销，不再重复扣除，也不只拿 hook_time 代替总开销。

若实测不支持 OOF 收益、正确性不通过或开销无法证明满足目标，记录失败/限制并停止晋级，不通过持续追加样本把结果调到过关。

## 7. P4：一次解封的真正独立确认

仅在 P3 通过、数据可得且预算够时启动。先提交 `configs/stage2_freeze.json`：代码/二进制/策略/分析 SHA、唯一候选、SBS、对照、指标、seed、名单、验证及停止条件。新测试求解结果必须在冻结后才产生/查看；不得运行新方法后据胜负决定纳入。

目标为 96 个真正未使用的实例、至少20个家族组，seeds 0/1/2，T=300 s；对所有先前使用的数据（包括旧 test/t2026、派生与符号变换）做 CNF hash、isohash/可用规范化去重及家族别名核对。主确认要求与开发/选择过程中接触的家族组不相交；保存来源、许可/下载、hash、排除理由及实际分布。旧年份的新实例可用，但应称新来源确认，不能称未来年份外推。不能把旧未解、旧未单独分析或重命名的数据当独立测试。

最多5个唯一配置：主要在线候选、I−、D、F−、P3 冻结的最强非内容基线（包含固定调度/静态/时间规则的竞争）；如重复可合并，不能看到结果后替换。所有结果统一验证，错误/缺失会阻止正式验收，不能只删除失败行。

主要性能标准：相对冻结的开发阶段 SBS，mean PAR2 降低≥5%，paired family bootstrap 95% CI 下界>0，平均 solved 不低于该基线；SBS 若不是 I−，仍单列相对 I−结果。要声称“在线内容观测有价值”，还必须在预定比较中优于最强非内容基线并给出区间，不能把静态编码识别或固定调度收益算作在线内容贡献。家族为重采样单元，先聚合 seeds；多项次要检验与探索分层独立标注，不能替换主检验。

报告失败类型、每 seed、各家族及事后 SAT/UNSAT 分层、收益集中度、v2 开销与所有尝试。冻结后一次解封，不据新测试再改策略。小样本/少家族导致区间宽时应写“证据不足”，不写“不存在更好的策略”。

若找不到符合条件的新数据，继续完成开发证据和可复现候选，交付“泛化未验证”的准确状态；本轮不以无限收集数据为结束条件，不复用旧评估集伪造独立性。

## 8. 最终交付与完成标准

至少交付并互相链接：

- `docs/STAGE2_PROTOCOL.md`：运行前提交的完整规则与变更记录。
- `reports/stage2/ENGINEERING_CHECKS.md`、`HEADROOM.md`、`LEARNABILITY.md`、`MULTISWITCH.md`（未启动也说明门槛/预算原因）、`CONFIRMATION.md`（未启动/无独立数据也如实记录）。
- `results/stage2/`：计划全集、不可变运行/配对/分折/特征/动作/成本记录、异常清单和hash；大日志/证明位置可追溯。
- `reports/stage2/FINAL_REPORT.md`：收益空间分解、预测与部署差距、阶段门槛、独立确认或缺口、机制解释的证据范围。旧冻结结果与新开发/确认结果分开呈现。
- `reports/stage2/COMPUTE_LEDGER.md`、README、DESIGN、实验日志与一条实际跑过的小型复现命令；原始记录缺失或资源阻塞需给出恢复步骤。

完成本阶段不要求正结果。可以完成为：发现并确认有效策略；确认某个有限候选集合收益很小；发现 oracle 空间但现有观测学不出来；只支持同族而无法迁移；或在预算内仍证据不足。**每个结论必须绑定候选集合、数据分布、预算和统计精度，不能把未实施/未充分检验写成已否定。**

按 P0→P1→有条件的 P2/P3/P4 自主推进，阶段性提交、保存证据并持续更新状态。只写代码/文档不等于实验完成；也不要为追求正结果无限调参、扩大预算或反复使用测试集。
