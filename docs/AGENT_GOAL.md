# Agent Goal v8：在不同类型、规模与难度的问题上研究三种 flag 的适用条件

设定日期：2026-10-23（美东）。状态：目标已设定；v8 试采样与正式实验尚未执行。

依据用户要求，下一阶段加入非比赛题与可控生成的问题，先在合理成本下观察 D / F+ / F− 的优势分布，再寻找简单的识别规则。**先三种模式完整运行，再看优势题的特点；主指标继续使用同一批题全部完成后的平均 CPU 时间。**

v7 原目标完整存档于 [AGENT_GOAL_COMPLETION_V7.md](AGENT_GOAL_COMPLETION_V7.md)，[长时报告](../reports/completion_v7/REPORT.md) 与原55题保留。该面板仍未全部完成，其完整平均仍为未知；v8 是独立的新数据研究，不能删掉原难题后重报旧面板成绩。

## 1. 起点与问题

在提交 8727837b07c76e69ad2f9c6499b4ba7e4ec97acf：

- v7 默认与冻结选择器只完成47/55题；剩余8题各已实际运行约12,250秒。55题中46题是大公式，继续等待旧面板全部完成的成本很高。
- 两道 sat-x 题，F− 约44和50秒完成，D 超过12,200秒仍未完成；优势确实存在，旧选择器却两题都选D。
- v4以来已用195.89/200 CPU核时，剩约4.11。启动任何新运行前先核对实际账本，不自动增加总预算。

本轮研究：

1. 在规模可控、难度从秒级到分钟级的新题上，三种模式的优势是否随问题结构、规模或编码发生规律变化？
2. 哪些差异来自正负极性、短子句/传播或基数约束编码，哪些只是生成器或编号的偶然性？
3. 低成本观察能否在留出的新实例上带来净时间收益？观察开销何时已经超过潜在收益？

比赛题不再是本轮数据来源的硬要求。保留近五年比赛数据作为旧外部困难面板；不要求先完成旧55题才开始v8，也不以新题成功替代旧面板的未完成结果。

## 2. 数据：三类问题，三档规模，先9题试采样

### 2.1 优先的三类

| 类型 | 生成/来源 | 可控因素 | 研究价值 |
| --- | --- | --- | --- |
| 随机 k-SAT | CNFgen；SATLIB随机SAT可作补充对照 | 变量数、子句密度、子句长、预先固定的文字极性分布 | 分离规模、约束密度与方向偏置 |
| 图着色 | CNFgen；SATLIB图着色 | 顶点数、边密度、颜色数 | 同一类结构逐步放大，检查赢家是否改变 |
| 基数约束组合 / 小型任务分配或排程 | PySAT基数编码 + 可复现的任务生成脚本 | 任务/资源数、容量与约束松紧、编码 | 检查问题结构、辅助变量与CNF编码的影响 |

基数类必须包含相互耦合的约束，例如每任务恰分配一个资源、资源容量和冲突约束；不能只生成一个容易被预处理直接解决的孤立 at-most-k 约束。预处理直接解出的题仍保留为真实对照，但不将它们当作决策方向有效性的证据。

来源入口（实施时固定确切源码版本与使用的命令）：

- SATLIB：https://www.cs.ubc.ca/~hoos/SATLIB/benchm.html
- CNFgen：https://massimolauria.net/cnfgen/benchmarks.html
- PySAT基数编码：https://pysathq.github.io/docs/html/api/card.html

SATLIB只是可用的现成题库，不要求把其所有集合都加入。优先可参数化、可重新生成的题。单个CNF的变量/子句数不是难度本身，必须同时记录搜索是否进入决策、冲突数、简化行为和实际时间。

### 2.2 试采样与尺度校准

- 起步9道基础题：3类型 × 3档规模，每格1题，使用独立的pilot seed；每题先运行三种固定模式。
- 三档规模按该类问题的生成参数定义，不沿用v7文件大小的大/中/小标签。试采样后，目标时间量级约为1–5秒、5–30秒、30–120秒；这是独立pilot的尺度目标，不是正式评价截止，也不是保证每道题必然落在区间内。
- 固定一份有限候选参数网格，最多两轮试采样（总基础pilot不超过18题）。只根据完成成本、是否进入搜索和覆盖选择尺度，不根据哪个动作赢、F±获胜率或某个特征相关性选生成器/参数。
- pilot可以设置180 CPU秒的单次行政保护，并受本节总预算约束；未完成照样记为未完成，仅用于校准尺度，不作为完整时间主成绩。
- 若全是毫秒级或都在预处理结束，可在网格内增大参数；若某档在pilot已明显超出可承受成本，用新的pilot seed校准更低参数。保留所有pilot记录，不反复调到forcephase恰好更好。
- 大多数正式题应有实际搜索空间，少量极快题作为观察开销的对照。不能声称“小问题一定容易”。

## 3. 正式数据集：目标90题，先冻结规模再运行

默认目标90个基础实例：3类型 × 3规模 × 每格10个独立seed。pilot实例不进入正式集。若pilot显示预算承担不了90题，允许在正式运行前统一改为54或27题：

| 总基础题数 | 每个类型×规模格的题数 | 开发 / 留出（每格） | 合计开发 / 留出 |
| --- | ---: | --- | --- |
| 90 | 10 | 7 / 3 | 63 / 27 |
| 54 | 6 | 4 / 2 | 36 / 18 |
| 27 | 3 | 2 / 1 | 18 / 9 |

选择N的规则必须在pilot前写定：根据各格三动作pilot的保守成本估计、验证/观察/策略实测成本与剩余算力，选能承担的最大预列规模，并预留长尾余量。小pilot不足以保证正式题全部完成，报告中须保留这一限制。正式集一旦冻结，不再因难题、超时或不利赢家改N、换题或删格。预算连27题也不支持时，只交付pilot和具体资源缺口，不冒充正式结论。

冻结内容：

- 类型、规模参数、公式生成器/编码器版本、所有命令、生成seed、CNF校验和、重复/同构核对、基础实例ID；
- 固定开发/留出分割、度量、计时/证明政策与账本。所有split只用生成身份，不能看正式胜负后划分；
- 基数类主实验先固定一种标准编码。额外编码、全局换号、随机变量重排均作另行登记的配对机制检查，不充作新的独立基础题；预算不足可以不做。
- 同一图、排程或基础公式的编码/换号/重排变体始终同组，不得跨开发与留出。禁止同一CNF换名灌入样本量。
- SAT/UNSAT生成构造与实际结果可以用于离线分析，但真实SAT/UNSAT、隐藏模型、生成seed、题目ID、来源名或类型标签不作部署输入。不要根据正式结果事后筛成“均衡且容易赢”的集合。

本轮首先检验同类结构上的新实例泛化，不能把开发/留出都包含三类型的结果称为“未见问题类型泛化”。留一类型分析可作为后续诊断，不用于反复调留出集规则。

## 4. 执行顺序与识别方法

### S0：运行前协议

先提交 docs/STRATIFIED_PROTOCOL_V8.md 与 configs/stratified_v8 下的具体配置，再跑pilot。目标机器摘要见 [goal.json](../configs/stratified_v8/goal.json)，它不是已经生成的正式数据清单。协议需列出参数网格、seed、尺度/N选择规则、预算、模型/阈值小网格与数据曝光状态。

保留固定CaDiCaL c60730422e758ef1cebe7aeddf2dda31c996bf04，正式动作 D(--phase=1 --forcephase=0)、F+(--phase=1 --forcephase=1)、F−(--phase=0 --forcephase=1)，seed0与独立答案验证。生成seed与solver seed分别记录，不混为一谈。比较的是包含rephase影响的配置包。

### S1：三固定模式先完整跑完

在冻结的新面板上运行D、F+、F−，分别取得完整时间。正式求解无评分截止，仍执行行政资源保护。全题未完成时，对相应模式保持null；不得恢复300/600惩罚。

先交付 BASELINES.md：

- 按问题类型、规模和实际难度，画三模式的完整平均、逐题时间比、赢家分布与收益集中度；
- 报告预处理直接解出比例、观察前已能结束的题、接近组和D优势题，不能只展示F±赢家；
- 以完整时间定义优势/接近组，原始绝对秒数差与比值都保留。新题可能只有几秒，不能机械沿用旧“加1秒平滑”的标签；“明确优势”阈值根据pilot的计时重复与实际开销事先固定；
- 若三者差异很小，先说明可利用空间有限，不强行训练能获胜的分类器。若开发证据显示oracle空间已经不足以覆盖实际观察成本，可按运行前规则跳过训练，记录为“未开展选择器研究”，不能冒充两种方法已经失败。

数据保管与分析可先完成固定运行的总表，但开发人员只看开发题胜负；留出题的特征/时间和模型结果在规则冻结后解封。计算oracle和主均值的自动脚本不应把留出结果提前显示给建模流程。

### S2：先看优势题的共同特点，再做至多两种简单规则

优先画少量能解释的对照：加权正负极性、短子句比例、单位/二元子句、规模与密度、便宜的方向传播差异；必要时只在开发题上检查局部搜索起点差异。先复用已有工具，起步约8–12个指标，不重新全采80项观测。

只比较两种固定的小方法：浅规则树（深度≤2）与正则化绝对时间差回归，均允许证据不足保留D。阈值以真实秒数节省为目标，在开发集按基础实例分组选择；禁止继续使用600惩罚标签或旧300秒成功概率作为优化目标。若需要内层分折，变体永远同折。

区分结构信号与规模信号：报告只用规模的对照，以及加入方向/约束特征后的增量。只有新增特征在相同读出器下有收益，才说新观测有用。

在线观察预算以实际CPU和总进程树计时为准。优先廉价静态/传播指标，不能沿用旧大公式上几秒的探测而不计费。对极快题检查是否应直接D。可在开发分析中报告“观察占默认时间的比例”，但部署不能偷用尚不知道的默认完成时间来决定预算。相对开销目标不是免费的在线先验。

### S3：冻结至多一个策略，在留出题上真实求解

- 用开发证据选至多一个最终策略，冻结特征、代码、阈值与模型，然后解封留出并实际运行完整wrapper。
- 先观察再选择一次正式动作。算法内观察、探测、重启与正式求解全部计时，独立验证通过才算完成。
- 主比较使用整个固定留出集的完整算术平均CPU与总CPU；D/F±/oracle对照来自同一留出集合。最佳固定动作SBS只能在开发集按总CPU选定，再在留出集比较。必须同时报告相对D和相对SBS的收益；只胜过D、未胜过SBS，只能说明该分布更适合某个固定flag，不能宣称在线识别有增益。不要用各方法各自完成的题作分母。
- 留出所有题完成后才能计算该方法的均值和收益。完整比较仍未知时，报告缺口，不按已完成子集宣布成功。
- 报告逐题正/负收益、支持量、错误偏离、观察成本及计时条件。小样本的区间需按独立基础实例/预定分层计算并说明只有三种生成类型；不能把变体或重复当独立样本，也不能凭3个类型bootstrap宣称广泛跨家族结论。
- 不依赖留出结果返调模型。参数/规模外推或新类型测试只有在资源与新冻结协议允许时另行开展。

## 5. 预算与旧面板边界

**累计200 CPU核时上限不变，不自动增加预算。** v7账本已记195.89，启动时核对是否有更新，再按实际剩余运行。未运行的v7困难题不自动追加重跑；旧55题及其null结果原样保留。

以暂余4.11核时为例，本轮规划：

| 项目 | 规划CPU核时（含该项失败/重跑） |
| --- | ---: |
| 生成、试采样与尺度校准 | 0.75 |
| 正式三固定模式、特征与留出wrapper | 2.50 |
| 检查器、建模、分析与报告 | 0.60 |
| 预留 | 0.26 |
| 合计 | 4.11 |

这是阶段规划，不保证90题能够在其中全部完成。生成、证明检查、作废尝试和模型拟合都入账。每批调度前根据实际剩余与上界调整计划；N只能在正式清单冻结前按规则下调。总上限达到时停止新增工作并交付完整进度，不能通过放宽计时、削弱正确性、删掉正式难题或挑选有利结果满足目标。若无法完成，明确指出是实验未完成，不宣称forcephase或识别方式无效。
