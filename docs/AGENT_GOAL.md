用户明确要求：**不采用超时惩罚，也不把超时按 300 秒截断计入主分数；让同一批任务真正解完，再比较平均时间。** 本目标取代 v6 的当前执行入口。已完成的 v6 目标存档：[AGENT_GOAL_STABLE_SELECTION_V6.md](AGENT_GOAL_STABLE_SELECTION_V6.md)；历史报告：[v6 FINAL_REPORT](../reports/stable_selection_v6/FINAL_REPORT.md)。

## 1. 唯一主指标

固定同一份 N 题清单，对方法 S：

- 单题时间 t(i,S)：从该方法启动到给出有效答案的完整进程树 CPU 时间，包括观察、试跑、特征、决策、读取/启动、算法自身的重启及正式求解。SAT 模型 / UNSAT 证明必须独立检查通过；证明生成计时，独立检查器时间另列并计入研究算力账本。
- 主指标 MeanCompletedCPU(S) = sum(t(i,S)) / N，取算术平均；总耗时为 N × 均值。越低越好。
- 相对默认收益 = 1 − MeanCompletedCPU(S) / MeanCompletedCPU(D)。
- 只有该方法在固定清单上的 N 题全部有效完成，才能发布它的完整均值。只要仍有一题未完成，均值、总完成耗时和涉及该方法的收益都保持未知 / null，并列出待完成实例。

不填入 300、600、超时倍数或其它有限惩罚值；不删难题；不采用“各方法各自成功题”的平均；不以中位数、几何平均或运行到上限的时长替代新主指标。旧 PAR2 和 300 秒截断平均仅作明确标注的历史辅助数据。

详细规则及评价入口见 [COMPLETION_TIME_PROTOCOL_V7.md](COMPLETION_TIME_PROTOCOL_V7.md) 和 [机器配置](../configs/completion_v7/protocol.json)。

## 3. 执行顺序

### C0：先接好新评价口径

- 核对协议、固定清单、计时与记录 schema；先运行新的评价检查，确认未完成数据输出 null。
- 增加长时运行入口，显式区分“正式求解无评分截止”与调度/配额的行政限制。现有 v6 wrapper 会在剩余 300 秒预算用尽时停止，不能原样当作 v7。
- 禁用 600 秒伪标签与 300 秒成功概率作为新目标。可以冻结 v6 的选动作逻辑进行长时复评，但必须命名为 P1_M05_long，并明确它原本针对旧目标训练；改动仅限计时政策和正式运行停止条件，不在 55 题上调模型。
- 旧已解出记录只有在参数、二进制、seed、证明政策与实际 CPU 来源核对一致后才能复用。旧 cost=600 不能导入为 CPU 时间。保留来源 run_id 和复用审计。

### C1：优先补齐默认基线

让默认 D 在全部 55 题上得到经验证的完成时间。旧 300 秒超时记录说明结果未知，不是完成时间。能保持活进程就延长同一次搜索；若已终止且无可靠检查点，必须从头运行，不得把日志当作可续算状态。

按预先固定顺序公平调度待完成题，报告每题当前状态及已花费 CPU；不因为某题太难而静默移除。行政中断仍为未完成，不能折算成评分。

### C2：测定 oracle 的真实空间

oracle(i) = min(t(i,D), t(i,F+), t(i,F−))，不含预测/观察成本，是事后最优参考，不是已实现策略。

为了节省测量算力，可以使用严格的“不可能更快”证据：已有一个经验证的动作在 b 秒完成，另一个动作要么有完整时间，要么已经在相同运行政策下实际执行到至少 b 秒而未完成。所有动作都满足此条件时，这题的最小值才确定；否则继续待定。CPU 下界来自实际运行，不能来自 PAR2、请求的作业上限、OOM 或错误退出。

这样不必为了 oracle 等待所有慢模式全部完成；但默认 D 的完整基线仍必须补齐。若也要比较 F+ 或 F− 的完整固定模式平均，则这些模式仍需全题完成。

### C3：按新指标复评现有策略，再决定方法研究

冻结选择器长时版必须在同一批 55 题上全部完成，完整计入观察/重启开销，再与 D 比较。不能只把其选中的固定动作 CPU 拼接起来冒充真实部署成本。

先回答“默认、oracle、当前选择器全部解完各需要多久”。只有获得适用的新时间标签后，才继续以总 CPU / 绝对秒数节省优化新规则；仍未解完的记录只作删失信息，不能当作精确训练标签。后续训练、调参、观察预算选择继续按家族分组，并另行冻结验证。

## 4. 算力、正确性与未完成状态

- 全部完成是评分条件，不是无限资源授权。v4 以来累计 200 CPU 核时上限保持不变；v6 已记 144.65，启动前先核对实际账本，暂余约 55.35。预留检查器、报告、失败与必要重跑成本。
- 作业墙钟 / 内存 / 配额限制不变成评价截止。达到行政上限后，保留未完成状态、当前有效下界、原因和算力账本；不发布伪装成完整结果的有限均值。
- 算法本身的观察、重启和重复尝试计入单题部署时间；因测量中断而作废的实验尝试另计研究账本，不拼成一次未实际发生的连续完成测量。重复测量的采用顺序需预先固定，不能选最快一次。
- 只有 SAT 模型 / UNSAT 证明独立通过的完成记录参与主分数。错误、OOM、未验证答案和缺失均为未完成。
- 预算不足以补齐时，交付“新口径尚未测完”的状态与具体缺口；不能据此宣布正结果或负结果，不能自动恢复 PAR2，也不能自行把剩余困难题排除。需要调整资源时，以实际待完成清单和支出为依据。
