# Agent Goal v6：识别稳定的 forcephase 优势子群

设定日期：2026-10-23（美东）。状态：目标已设定，v6 实验尚未执行。

本目标接续已完成的 v5。核心问题是：**能否通过低成本、可复现的观察，识别一小类稳定适合 F+ 或 F− 的实例，并在完整成本下获得可验证的收益？** 最终仍然是“先观察，再选择一次 flag”，保持课程任务的规模。

v5 原目标完整存档于 [AGENT_GOAL_OBSERVATIONS_V5.md](AGENT_GOAL_OBSERVATIONS_V5.md)。先读 [v5 最终报告](../reports/observations_v5/FINAL_REPORT.md)、[实际部署](../reports/observations_v5/DEPLOYMENT.md)、[覆盖与错误](../reports/observations_v5/COVERAGE_AND_ERRORS.md)、[工程诊断](../reports/observations_v5/V1_ENGINEERING.md) 和 [算力账本](../results/observations_v5/COMPUTE.md)。

## 1. 起点、范围与要回答的问题

已知起点（提交 919cd6d54d5c9ed52a369b3694ed2d5cd8d60e94）：

- 2022–2026 五年代表性面板 500 题，开发集 401、旧测试集 99。开发集原始单 seed 标签中，D / F+ / F− 强优势分别为 62 / 38 / 24 题。
- v5 实施 50 项新观测，另 1 项部分实施；27 个登记组合没有可靠优于始终 D。局部搜索选择器 dev 真实收益 −0.25%，新增 78 题上 +0.4% [−4.8, +6.0]，不足以认定有效。
- 已发现局部搜索按 CPU 时间停止导致不可复现、大公式观察经常无法完成、D 的单 seed 胜负不稳定。事后最优的 12%–13% 空间是单 seed、忽略选择难度的参照，不是可以保证实现的收益。
- v4 + v5 已使用 122.28 CPU 核时；启动前须核对是否还有后续支出。

本轮依次回答：

1. 原先 F+ / F− 优势是否能在有限 seed 重复中保留？
2. 修复后的局部搜索或成熟 SAT 特征，是否提供稳定的区分信息？
3. 简单规则或“解出概率 + 条件耗时”方法，能否抓住少数有收益的偏离，同时控制错误偏离？
4. 在新实例和完整 wrapper 中，收益是否仍然存在？

固定 CaDiCaL c60730422e758ef1cebe7aeddf2dda31c996bf04，正式动作仍只有：

| 动作 | 配置 |
| --- | --- |
| D | --phase=1 --forcephase=0 |
| F+ | --phase=1 --forcephase=1 |
| F− | --phase=0 --forcephase=1 |

D 是原生默认的 saved / target / rephase 配置包；forcephase 也影响 rephase，不能解释为只改变一个符号。正式求解 seed 固定为 0。多 seed 只用于鲁棒性诊断，不变成运行多个完整求解器的部署策略。观察后正式求解从头运行一次；不增加第四个动作，不继续研究搜索中反复切换。

v4 / v5 的全部结果都已曝光。旧 test99 和 v5 确认78只能作历史、诊断对照，不用于挑选 v6 候选，也不能重新称为盲测。v6 的 dev OOF 也属于曝光后的开发评估。原 401 题、原家族分组和总体评分均保留，不按是否容易获胜删题。

## 3. R1：确认优势稳定性（约 30 题）

从原 dev 中按旧标签选 D、F+、F− 优势各 10 题；不足时保留实际数量并说明。各组尽量覆盖至少 3 个家族及不同规模、年份，避免单一家族主导。抽样使用固定 seed 20261023，先发布清单，再运行，不能看复测胜负后换题。

每题三个动作补齐 seed 0 / 1 / 2，复用配置、输入与证明政策一致的已有运行，只补缺失。通常最多新增 30 × 3 × 2 = 180 次 300 秒运行，求解 CPU 上限 15 核时；检查器另计。

预先定义：令 c 为每题每动作每 seed 的 PAR2 成本，q(a,s) = (另两个动作中较小的 c + 1) / (动作 a 的 c + 1)。某动作在至少 2/3 个 seed 上 q ≥ 1.5，且其余 seed 上 q ≥ 1，记为“小面板内稳定优势”；同时报告完整连续成本、原标签保留率、赢家转换和超时转换，不只报告二元标签。

要求：

- 对三种原优势组分别报告，不能把原来只对 D 的小样本现象推广到全部模式。
- seed 不是新实例；此按赢家平衡的小面板不代表总体占比，不用于宣称总体收益。
- 主训练与主评分仍使用完整 dev401 的统一 seed0 成本；30 题重复是诊断，不把局部多 seed 标签悄悄混入其余单 seed 标签。
- 复用记录须保留时间/节点等差异；必要的计时重复在协议中预先指定，不从多次结果中挑最快的。
- 若强制模式的优势多数不稳定，仍完成有界分析与必要对照，但据此收缩后续探索，不能无限增加 seed 寻找有利结果。

交付 reports/stable_selection_v6/STABILITY.md、逐题长表和优势迁移图，明确“仅 3 个 seed 的初步稳定性”。

## 4. R2：修复观察，集中找可解释的差异

### 4.1 修复局部搜索与时间上限

这是本轮第一优先级的观测工作，沿用 v5 实现并保存旧版作对照：

- 对全0、全1、固定随机起点，使用固定翻转次数、固定随机 seed、固定平手处理；另设 CPU 硬上限保护。
- 在预选的 12 题工程面板上，以不超过两个工作量设置比较覆盖和开销，按工程表现固定一个设置，再采集 dev401。工作量不能按哪组胜负更好反复调。
- 修补解析、建出现表和各段循环的上限检查。固定工作量正常完成时，相同输入重复三次的非计时特征必须一致；实际 CPU 等计时元数据单独保存。被 CPU 上限打断时明确标记不完整并回退 D，不使用随计时变化的半成品特征。
- 记录翻转数、未满足子句数、下降曲线、三个起点的差异和实际 CPU。成功找到的候选赋值仍只作观测，不改变本轮正式动作范围。
- 先重现 v5 的不可复现现象，再给出修复后证据。不能仅以“随机 seed 固定”代替验证。

核心机制分析：稳定 F+ / F− 优势题与规模相近的 D 优势题之间，三个起点的残余违例和改善速度是否存在方向一致的差异？控制规模/家族后是否仍存在？使用配对案例和分布图；所有找出来的规律都标为开发假说，等待外部实例检验。未知 SAT/UNSAT、终局赋值和未来统计不得成为部署输入。

### 4.2 成熟 SAT 特征作为外部对照

尝试接入《Revisiting SATZilla Features in 2024》的官方特征工具中，能在本轮观察预算内完成的部分：

- 固定源码/依赖与许可证，登记与 S28、v5 特征的重叠，避免把旧特征换名当新增。
- 先测大公式的可用率和全部 CPU，再决定可用子集。不能直接套用文献中更长的特征时间预算。
- 若工具不兼容或预算不合适，以最多 2 CPU 核时的工程尝试为界，交付日志、具体原因和可用子集；不能无限修工具，也不能把未完成的对照标为失败实验。

特征提取研究依据：
- Shavit & Hoos, SAT 2024: https://doi.org/10.4230/LIPIcs.SAT.2024.27
- 官方研究代码入口见该论文的 artifact / source 链接。

此文献支持“值得做成熟特征对照”，不保证对同一 CaDiCaL 的三种 flag 有效。

## 5. R3：只做有限的选择实验

保留原家族分组外层 5 折、内层 3 折；预处理、特征选择、校准、阈值和超参数均只在相应训练部分拟合。同一实例的 seed 和编码变体永远同组。

固定三个输入包：

1. S28：旧 28 个静态特征；
2. S28 + 修复后的局部搜索；
3. S28 + 预算内的成熟 SAT 特征。

每个输入包只配两个主读出器，共最多 6 个核心比较：

- **RG**：v5 的绝对成本差 ridge + 默认回退门，作为同输入对照。
- **M05**：分别预测每个动作在剩余预算内的解出概率 p，以及解出后的条件平均耗时 m；用简单的正则化概率模型与耗时模型，不引入大型网络。

M05 的成本口径必须正确：若已用/预留观察及 wrapper 成本为 h，正式剩余预算 B = 300 − h，则预测 PAR2 为 p × (h + m) + (1 − p) × 600，其中 p 对应“在 B 内解出”，m 对应“在 B 内解出的正式 CPU 均值”。从已有固定运行构造训练目标时，超过 B 的结果按超时处理；不能把 300 秒超时当作真实运行时间，也不能对超时的 600 再加一次观察费。用于动作选择时比较同一观察后的 D，最终收益始终相对“不观察、始终 D”。

另外最多登记 2 条低复杂度规则，优先使用局部搜索正负起点差异或已有弱信号的结构/传播对称性。可以用深度不超过 2 的树表述；这不是一种全新算法，须说明相对 v5 浅树的具体差异。规则选择也必须进入分组验证。总新增候选上限 8，不补齐 80 项观测，不继续无界模型/阈值搜索。

必须同时报告：

- PAR2、解出数、观察成本、观察完成率、默认回退率；
- 正确偏离的节省、错误偏离的损失、D 能解而策略超时的数量；
- 子群支持量、家族数和收益集中度；完整总体包括接近组和全部超时组；
- 同一读出器下新增特征相对 S28 的增量，同一输入下 M05 相对 RG 的增量；
- 所有候选，不只最好的一个。全部回退 D 不能称为识别成功。

最多晋级 2 个候选。先在预先固定的至多 30 道 dev 实例上真实运行 wrapper，核实动作、观察开销、剩余预算和离线评分；这是部署检查，不作为新的泛化评估。不重跑全部 401 × 2 个完整 wrapper。

交付 OBSERVATIONS.md、SELECTION.md、原始特征/OOF 预测/损失分解和最多两张可解释规则图。

## 6. R4：冻结后验证新实例

目标为最多 60 题，2022–2026 每年约 12 题，保留家族与规模分层、来源与校验记录。先提交清单和曝光审计，再冻结代码、模型、阈值、观察上限、分析脚本与 seed0，随后才运行三个固定动作和至多两个候选 wrapper。

抽样与边界：

- 优先结果未接触的新实例，并与全部旧实例及变体做 hash / isohash / 家族核对。
- 在预先定义的候选池中按年份、规模和家族分层选样，不根据新动作的胜负筛题，也不只抽有利类型。
- 优先留出未参与 v6 开发的家族。v5 已发现原候选池的家族全部在 v4 曝光；若没有真正未曝光家族，明确写“新实例、已曝光家族的有限确认”，不能改称完全独立盲测。
- 稳定优势类型的额外案例可作为单独探索集，按独立预算登记；不能替换代表性评估集或混入其总体得分。
- 合格新实例不足时用实际数量，不以旧题填充。不为凑齐 60 题无限扩大下载或采集。
- 固定动作与 wrapper 尽量在同批次、同硬件条件分块交错运行，记录资源和计时差异。运行失败与截止线波动分开；补跑保留失败记录，不择优取最快一次。
- 解封后不再调阈值、改特征或挑规则；修改后的方法只能称后续开发，不能继续用此集证明泛化。

报告相对默认的配对收益及 95% 家族 cluster bootstrap 区间、解出数和逐题损失。可预设 PAR2 改善 ≥ 2% 为实用目标，可靠正收益需区间下界大于 0；小样本区间宽不能解释为证明无效。不要求为完成目标强行得到正结果。

## 7. 成本、预算与正确性

- 单题完整进程树的总预算保持 T = 300 CPU 秒。读取、解析、局部搜索、外部特征、临时探测、推理、重启和 wrapper CPU 全部计入；未在预算内解出或答案验证不通过，PAR2 = 600。
- 观察总硬上限保持 6 CPU 秒；优先争取多数实例在 0.5 秒左右完成，但此为工程目标，不通过删大题实现。预算触顶时保留足够启动/收尾成本并回退 D。所有进程的 CPU 相加，不能把并发视作免费。
- SAT 模型和 UNSAT 证明沿用独立验证。检查器 CPU、建模分析、失败/补跑、作废实验、重复运行均计入总账，不能只报成功求解时间。
- **v6 新增全部 CPU 上限 60 核时；v4 + v5 + v6 累计仍不得超过 200。** 当前已记 122.28，按计划最多到约 182.28；启动时以核对后的实际账本为准。本目标取代 v5 协议的阶段性 150 核时停止阈值，不改变累计 200 的上限。
- 每批提交前按最坏运行数估计剩余预算，满足不了则缩小后续批次并记录，不超支、不购买算力。

| 阶段 | 含检查/失败/分析的规划上限（CPU 核时） |
| --- | ---: |
| R0/R1：协议、30题多 seed 与分析 | 16 |
| R2/R3：工程、dev特征、建模 | 8 |
| dev真实 wrapper 检查 | 6 |
| 新实例确认与校验 | 28 |
| 预留 | 2 |
| 合计 | 60 |

60题 ×（3固定 + 2候选）× 300秒的求解上限是25核时，检查与重复还须另留余量。各项是上限，不是配额；根据实际账本滚动调整。无可用候选时不强制部署两个，无合格新数据时交付明确缺口。

## 8. 交付物、结论与停止条件

继续 research/forcephase-study，及时 commit/push，不强推；保留 v4/v5 协议、冻结标签、旧工具与结果。v6 新产物分别使用：

- configs/stable_selection_v6/：面板、配置、注册比较、冻结模型与哈希；
- scripts/stable_selection_v6/：分析、采集、训练、部署脚本；
- results/stable_selection_v6/：逐题记录、特征、预测、完整 COMPUTE.md；
- reports/stable_selection_v6/：STABILITY.md、OBSERVATIONS.md、SELECTION.md、VALIDATION.md、FINAL_REPORT.md；
- docs/STABLE_SELECTION_PROTOCOL_V6.md：在实验前具体化本目标，追加偏离记录。

最终报告用简洁中英文回答四个研究问题，附 3–5 张核心图（优势稳定性、观察差异、净收益/错误损失、确认结果）和一条实际跑过的最小复现命令。不得只交计划、训练代码或一张相关性图。

满足以下任一路径可完成这一阶段：

1. **可靠正结果**：冻结策略在新实例完整成本下优于 D，披露区间、支持量、家族覆盖和全部错误损失。
2. **局部正结果**：一条预先冻结的规则在留出数据上识别出有收益的子群；明确适用范围与总体结果。支持不足或来自同一家族时仅作案例，不能宣称普遍可迁移。
3. **有界负结果**：完成稳定性诊断、观察修复、限定的外部特征/M05对照与可行的冻结验证；明确瓶颈是标签不稳定、信号不足、观察成本、错误损失还是数据不足，并逐项记录未做内容。

默认门应当服务于安全偏离，但“几乎总选 D”本身不是本轮希望发现的识别规则。目标是得到可信、能解释、可复现的研究结论；若仍无收益，完成并停止本轮，不自动追加新一轮方法或无限扩大数据。
