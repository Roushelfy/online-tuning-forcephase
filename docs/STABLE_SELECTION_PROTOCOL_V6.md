## 2. R1：优势稳定性（只是诊断）

**运行**：
- 诊断 30 题，每题三个动作，seed 1 和 seed 2 各跑一次。正式政策与 v4 相同：`build/fpc`、T = 300 s、16 GB、LRAT、遥测，在命令行加 `--seed=s`。
- 实验配置为 `configs/stable_selection_v6/v6_seed1.json` 和 `v6_seed2.json`。
- seed 0 直接用 v4 的 dev 固定运行。
- seed 1 中与 v5 seed 重复（`v5_seed1`）相同的 21 次运行按运行 id 自动复用，因为配置、输入与证明政策都相同。
- 新增 159 次运行，最坏情况 13.3 求解核时。每次复用都记录原运行的节点和时间。

**指标**：
- c(a, s) 为 PAR2 成本；q(a, s) = (另两个动作中较小的 c + 1) / (c(a, s) + 1)。
- 若动作 a 在至少 2 个 seed 上 q ≥ 1.5，且其余 seed 上 q ≥ 1，记为“小面板内稳定优势”。
- 同时报告：完整的连续成本、原标签的保留率、赢家转换和超时转换。三种原优势组分开报告。

**不做的事**：
- 不加 seed、不换题，也不从多次运行中挑最快的。
- 不另做计时重复：F± 在不同 seed 下几乎总是同一搜索（v5 已观察到），它们的 seed 运行就是天然的计时重复，单独报告。

**主训练与主评分**：仍然只用 dev401 的 seed 0 成本，不把这 30 题的多 seed 标签混进去。

**收缩规则**（预先固定）：
- 若原 F+ 与 F− 优势题中，“稳定优势”的合计比例 < 30%，R3 仍完成全部 8 个比较（成本很低），但 R4 只部署 1 个候选；
- 否则至多部署 2 个。

## 3. R2：修复观测

### 3.1 可复现的局部搜索与上限检查

新建工具 `tools/obsprofile6.c`，从 v5 的 `tools/obsprofile.c` 复制而来；v5 工具原样保留，作为对照。改动如下：

- **局部搜索段**：
  - 全 0、全 1、随机三个起点，每个起点**固定翻转次数 W**；
  - 每个起点用独立的固定随机流（seed 20261023 + 1000 + 起点编号），平手处理固定；
  - 整段另设 CPU 硬上限 1.0 s。触顶时整段状态记为 `cap`，不输出半成品特征，该包回退 D。
- **记录内容**：每个起点的翻转数、未满足子句数（初始、1,000 次后、W/4 次后、W 次后、最好值）、下降曲线、三个起点之间的差，以及实际 CPU（作为计时元数据，单独保存）。
- **上限检查**：解析、建出现表、每段的构建与主循环，都加上周期性的 CPU 检查。
- **W 的选择**：比较 W ∈ {10,000, 50,000}。规则预先固定，只看工程表现，不看胜负：
  - 在工程 12 题上运行两种设置；
  - 若 W = 50,000 的局部搜索段在 ≥ 10/12 题上正常完成，且中位 CPU ≤ 0.3 s，就选 50,000，否则选 10,000。
- **可复现性检验**：
  - 先在工程 12 题上把 v5 的局部搜索段重复运行 3 次，重现“特征随计时变化”的现象；
  - 再用 obsprofile6 在所选 W 下对同一输入重复 3 次，要求所有非计时特征逐项相同；
  - 结果写入 OBSERVATIONS.md。

### 3.2 SATzilla 2024 特征（外部对照）

- **构建**：在容器中从源码构建 `features`（`make feature`），登记 commit、依赖与二进制的 sha256。
- **特征组**：
  - 不用 `ls`（调用仓库自带的预编译 ubcsat）和 `cl`（预编译 cadical2023）；
  - 用 `--preprocess-timeout 0` 跳过外部预处理器（预编译的 sbva）；

## 4. R3：选择实验（总共至多 8 个登记比较）

**输入包**（S28 始终来自 obsprofile6 的同一次解析）：

| 包 | 观测 | 静态上限 |
| --- | --- | --- |
| P1 S28 | obsprofile6 `s28` | 3 s |
| P2 S28 + LS6 | obsprofile6 `resid, ls`（所选 W） | 3 s |
| P3 S28 + SZ | obsprofile6 `s28`，加上 SATzilla 所选组 | 两部分合计 3 s |
| P4 规则用 | obsprofile6 `resid, bilat, graph`（与 v5 相同的、可复现的部分） | 3 s |

**读出器**：
- **RG**：沿用 v5 的 ridge 门。对 F+ − D、F− − D 的成本差回归，α ∈ {1, 10, 100}，θ ∈ {0, 2, 5, 10, 20, 50, 100, ∞}。
- **M05**：对每个动作 a，分别预测两件事：
  - p_a：在剩余预算 B = 300 − h − 0.1 内解出的概率，用 L2 logistic，C ∈ {0.1, 1}，类别不平衡时不加权；
  - m_a：在 B 内解出时的条件正式 CPU，用 log1p 尺度上的 ridge（α = 10），再乘 Duan smearing 因子换回秒。

  训练目标由固定运行构造：t_a > B − 0.1 视为超时，h 是该实例在本包下的观察加 wrapper 成本。预测 PAR2_a = p_a·(h + m_a) + (1 − p_a)·600。只在 PAR2_D − min(PAR2_F+, PAR2_F−) > θ 时偏离，θ 用同一网格。
- **规则**（2 条，都是深度 2 的回归树门）：
  - **R-LS**：只用 LS6 中三个起点之间的差，共 6 个预先指定的特征（`l6_` 前缀，定义见工具）；
  - **R-SYM**：只用 v5 中有弱信号的结构/传播对称特征：`b03_props_lr_top16`、`b03_props_lr_mean`、`d01_reach_lr_mean`、`d01_reach_pos_gt_frac`、`c04_inverse_share`、`b02_fail_any_frac`。

  与 v5 的 TG 相比有三处不同：
  - 特征限定为预先指定的不超过 6 个；
  - 深度固定为 2，min_samples_leaf = 15；
  - 一个叶子只有当其训练支持量 ≥ 15 题、来自 ≥ 3 个家族组、平均收益 > θ 时，才允许偏离。

**比较**：
- 登记比较共 8 个：P1、P2、P3 × {RG, M05}，加上 R-LS 和 R-SYM。
- 对照：始终 D、事后最优、v5 的 R09|RG（只作历史参照）。
- 交叉验证用 v5 的外层 5 折（等于 v4 的折）和各外层的内层 3 折（`configs/observations_v5/folds.csv`）。预处理、阈值、超参数都只在训练部分拟合。
- **成本**：沿用 v5 第 5 节。κ 取实测的 wrapper 开销：用 v5 的 κ = 0.032 s（静态包）。P3 另加 SATzilla 进程的 CPU。

**必须报告**：
- PAR2、解出数、观察成本、观察完成率、默认回退率；
- 正确偏离的节省、错误偏离的损失、D 能解而策略超时的数量；
- 偏离子群的支持量、家族数与收益集中度；
- 同一读出器下 P2/P3 相对 P1 的增量；同一输入下 M05 相对 RG 的增量；
- 全部 8 个比较，以及按优势组的分解。

**断言规则**：同 v5 第 7 节。只有配对区间不含 0 才说“有用 / 改善”；全部回退 D 不算识别成功。

**晋级**：
- 按 OOF 净收益点估计，取 > 0 的候选，至多 2 个；R1 的收缩规则可能把上限降为 1。
- 若没有 > 0 的候选，只晋级 OOF 净收益最高的 1 个，标为“负对照部署”，用来在新实例上检验有界负结论。

**真实检查**：在检查 30 题上用折模型真实运行晋级候选的 wrapper，核对动作、观察开销、剩余预算与离线评分。这只是部署检查，不是新的泛化评估。
