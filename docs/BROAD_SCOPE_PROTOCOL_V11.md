## 0. 固定项

- **求解器与动作**：沿用 v10，CaDiCaL c607304（3.0.1），命令为 `build/fpc/cadical --lrat=1 <动作> --fpc=1`，seed 0，内存上限 RLIMIT_AS 16000 MB。

  | 动作 | 参数 |
  |---|---|
  | D | `--phase=1 --forcephase=0` |
  | F+ | `--phase=1 --forcephase=1` |
  | F− | `--phase=0 --forcephase=1` |

- **答案检查**：SAT 答案用 checkmodel 检查，UNSAT 答案用 lrat-trim 检查。检查失败记为未验证，不算已解，也不自动当作求解器答错。检查器的 CPU 单独记账。
- **生成题的语义检查**：每个 SAT 模型额外按问题本身解码并检查（第 3.3 节）。
- **单次上限**：每题每方法的完整进程树最多 3600 CPU s，包括静态分析、probe、推理、停止、重启与正式求解。项目与阶段的累计核时不设上限，全部实际成本照常记账。
- **计时与报告**：
  - 某方法在某面板上全部完成并验证后，才报告完整算术平均 CPU；否则均值为 null，依赖它的收益也为 null。
  - 有超时的面板，报告已解数、配对新增与丢失、CPU 解题曲线和删失状态。
  - 3600 不当作完成时间，不用 PAR2。
- **调度**：使用 cpu-mid（cpu-low 可被抢占，见 v10 第 12 节），sbatch 加 `--no-requeue`。被平台中断的运行到新 stage 重跑，并记入偏离。
- **曝光**：v4–v10 的全部数据都已曝光，包括旧比赛面板、旧留出、外推与 SATLIB 外部集。它们只用于探索、代码复用和历史对照。审计见 SOURCE_AUDIT，不把旧负结果换个名字重做。

## 1. 部署语义

wrapper 是 [scripts/broad_scope_v11/wrapper.py](../scripts/broad_scope_v11/wrapper.py)，即 v10 wrapper 加上 v11 的决策函数。v10 的语义原样保留：

1. 静态分析：`build/tools/static10`，CPU 上限 2 s，工作量上限 5×10⁷。超过上限时，静态特征记为缺失。
2. probe 用该臂的正式命令运行，窗口 τ 为该进程自己的 CPU，包含解析。
   - probe 给出答案时直接结束，答案经检查后复用。
   - 否则读取停止时已经写出的输出，按 `common.decide` 选择动作，然后 exec 该动作从头求解。
   - exec 前把内核 CPU 上限设为剩余预算。

v11 只增加一条规则：策略可以带 `ood` 字段，记录训练折中每个特征的范围。任一列出的特征缺失或越界时，直接取 `ood.action`（路径记为 `ood`），不再咨询读出器。不带该字段的策略与 v10 完全相同。

静态树和类型路由都编译成叶子为动作的树，复用 v10 的 tree 代码。

在线输入只有 CNF 文件本身和 probe 输出。文件名、来源、家族名、生成 seed 与答案都不作为输入。

## 2. 状态

| 状态 | 含义 |
|---|---|
| `solved` | 已验证答案，CPU ≤ 3600 |
| `policy_timeout` | 达到上限（控制器停止，或内核在上限处发 SIGXCPU，见 v10 第 12 节的规则修正） |
| `wrong` / `unverified` | 检查失败 |
| `measured` | 开发测量运行 |
| `censored` | 平台中断 |

## 3. 生成家族（S1）

### 3.1 八个语义家族

所有生成器都由 (规模, seed, 参数, 编码) 完全确定，CNF 不含注释，清单记录 SHA-256、子句集哈希与改名不变哈希。

| 家族 | 语义任务 | 规模参数 | 主编码 | 替代编码 | 生成器 |
|---|---|---|---|---|---|
| rand3（桥接） | 阈值附近的均匀随机 3-SAT，m = round(4.26 n) | n | CNFgen randkcnf | —（无语义上不同的编码） | v9 原样 |
| col3（桥接） | G(n, round(2.3n)) 的 3 着色 | n | CNFgen kcolor（direct） | log：每顶点 2 位，禁止取值 3 | v9 原样 + `families.col3_log` |
| assign2（桥接） | v9 耦合分配，结构 F | T | PySAT 顺序计数器 | — | v9 原样 |
| vcover（基数） | G(n, round(d n/2)) 是否有大小 ≤ K = ⌊αn⌋ 的点覆盖 | n | 顺序计数器（Sinz） | totalizer（PySAT CardEnc） | `families.vcover` |
| jssp（调度） | n×n job-shop，每个作业的机器顺序随机，工期 U{1..dmax}；判定 makespan ≤ T = ⌈β·LB⌉，LB 取作业长度与机器负载的最大值 | n | order encoding（开始时间的顺序变量 + 机器对的先后变量） | time-indexed（开始时刻变量；同机同时刻成对互斥） | `families.jssp` |
| bwplan（规划） | n 块积木，随机初始与目标状态，判定是否存在 ≤ T = ⌈γL⌉ 步的顺序计划（L = 未就位块数，是最优长度的下界） | n | 解释型框架公理，每步至多一个动作（梯形编码） | — | `families.bwplan` |
| factor（电路 / 位向量） | b 位 × b 位阵列乘法器 = N，p, q ≥ 2。任务由 seed 奇偶预先决定：偶数时 N 为两个随机 b 位素数之积（可满足），奇数时 N 为随机 2b 位素数（不可满足） | b | Tseitin 阵列乘法器 | — | `families.factor` |
| qcp（组合） | n 阶拉丁方补全，round(f n²) 个格子按随机顺序做一致的随机预填 | n | minimal：格 ≥ 1 值，每行/列每值 ≤ 1 | extended：另加格 ≤ 1 值、每行/列每值 ≥ 1 | `families.qcp` |

新增的五个家族满足目标第 4.1 节的要求：

| 目标要求 | 对应家族 |
|---|---|
| 基数约束可行性 | vcover |
| 独立调度 | jssp（有时间、先后与机器资源约束，与分配生成器无共享代码） |
| 规划 | bwplan（有状态转移与目标） |
| 算术电路 | factor |
| 组合结构 | qcp |

支持替代编码的语义家族有 4 个：col3、vcover、jssp、qcp。

已知限制（会在 STRUCTURE_MAP 中注明）：
- factor 的答案由任务预定，UNSAT 一半是素数证明，证明结构特殊。
- vcover 只有一个全局基数约束加 2-子句。
- bwplan 的随机状态不是在全部状态上均匀抽取：随机排列后，每个间隙以 1/2 的概率切开。
- qcp 的预填不做前向检查，所以部分实例在传播阶段就会被判为 UNSAT。

### 3.2 正确性检验（已在提交前完成）

[tests/test_broad_scope_v11_gen.py](../tests/test_broad_scope_v11_gen.py) 覆盖每个新家族和每种编码，每个规模用 12 个 seed 的极小实例。检验内容：

- PySAT MiniSat 2.2 对 CNF 的 SAT/UNSAT 判定与问题本身的穷举一致。
- 每个模型都能解码为合法解。
- 同一基础问题的两种编码答案一致。
- 每个家族都同时出现 SAT 和 UNSAT。

### 3.3 运行中的语义检查

生成题的已验证 SAT 运行保留模型行。`gen.py semcheck` 用生成器重新生成实例（同时核对 SHA-256），解码后在问题层面检查。

rand3 与 assign2 只做 checkmodel：前者没有语义层，后者沿用 v9 生成器。flipall 与 perm 变体也只做 checkmodel。

语义检查失败属于数据正确性问题，处理方式见第 12 节：记录偏离、修复后重跑，不静默删除。

### 3.5 独立 pilot（S1b，96 题，只跑 D）

8 个家族 × 3 档 × 4 题，seed 8000 起，只跑 D，单次上限 3600。

规模判定：一档的 pilot 中位数 D CPU 必须落在下表的带内。

| 档 | 带（s） |
|---|---|
| S | [0.3, 15] |
| M | [3, 150] |
| L | [20, 900] |

- 不在带内时，向需要的方向移动一个网格步，只移一次，不再重做 pilot。移动不得破坏 S < M < L 的顺序；会破坏时保持原值，并记录原因。
- 同时报告真实搜索覆盖：结束时 conflicts > 0 的比例。若 S 档少于 3/4 进入搜索，在 BASELINES 中注明“亚秒对照”。
- 不看 F± 的结果，pilot 也不运行 F±。
- 某家族即使到网格端点也得不到中等难度，就如实披露，不用大量亚秒题充数。

### 3.6 正式面板与分组

[panel_rule.json](../configs/broad_scope_v11/panel_rule.json) 定义各面板如下：

| 面板 | seed 起点 | 规模 | 构成 |
|---|---|---|---|
| 发现 | 1000 | 288 | 每家族每档 12 |
| 开发 | 2000 | 240 | 每家族每档 10 |
| 确认 | 3000 | 240 | 每家族每档 10 |

- 确认面板按 seed 次序分成三块，每块 80 题，八个家族每块各 10 题。档位分配为：块 1 是 S4/M3/L3，块 2 是 S3/M4/L3，块 3 是 S3/M3/L4，因此全 240 题每家族每档各 10 题。

## 6. S2：编码与符号控制

**基础问题**：从发现面板中，每家族每档取 seed 次序的前 2 题，共 48 题。

**变体**（全部归入其基础问题的组）：

| 变体 | 范围 | 题数 |
|---|---|---|
| `enc:<替代编码>` | col3、vcover、jssp、qcp 的 24 题 | 24 |
| `flipall` | 全部 48 题，全局文字翻转 | 48 |
| `perm`（seed 1） | 全部 48 题，变量重排加子句洗牌 | 48 |

工具为 `build/tools/cnfscramble` 与 `gen.py variants`。每个变体运行 D、F+、F−，共 360 次。

**solver seed**：每家族每档取 seed 次序的第 1 题，共 24 题，在 seed 1 和 seed 2 下各运行 D、F+、F−。

**等价性**：同一基础问题的各编码与各变体的已验证答案必须一致，不一致即视为数据错误。

**报告**（ENCODING.md）：
- 每个变体相对原题的最快动作是否改变，以及明显优势类别是否保持（20% 且 ≥ 1 s）；
- flipall 是否把 F+ 与 F− 交换；
- 偏好主要来自语义任务、规模、编码还是偶然编号。相关性不当作机制证明。

这些诊断若产生新规则，不在本轮检验，留给下一轮独立确认。

## 7. S3 与 S4：基线、结构地图与有限方法比较

### 7.1 BASELINES 与 STRUCTURE_MAP（只用训练池与诊断）

- 每家族、每档、每编码的三模式完成率与完整成本状态。
- 明显得失（20% 且 ≥ 1 s）、最大损失和收益集中度。
- oracle 的精确值，有超时时给上下界。
- 类型内与类型间选择空间的分解：把每家族换成其最佳固定动作，能取回整体 oracle 空间的多少。
- SAT/UNSAT 只做事后分层。
- 报告两种加权：家族等权，以及按实例总 CPU。

### 7.2 候选方法族

所有拟合都在训练折内完成，包括归一化、阈值、SBS、类型动作与范围界。

**选择准则 C**：先比较已验证解题数，多者胜；解题数相同时，比较实际消耗的总 CPU。超时运行按其实际消耗计入资源，这是资源量而不是完成时间。全部完成时，C 就等于完整总 CPU。

**方法族**（在线特征只有 static10 的 20 个静态指标，加上方法 5 的 D 前缀 10 个指标）：

| 方法 | 定义 | 内层网格 |
|---|---|---|
| SBS | 训练折上按 C 最好的固定动作 | — |
| V10（历史） | v10 冻结主策略（静态 + D 2 s，ridge，base F−），不重训 | — |
| ST 静态树 | 成本敏感树：叶子取按 C 最好的动作；只有当叶内总成本比训练 SBS 低至少 θ 比例时才偏离 SBS；最小叶 15；切分候选为训练分位数（十分位） | 深度 {1, 2, 3}，θ ∈ {0, 0.1, 0.25} |
| TR 类型路由 | 分类树由静态特征预测生成家族（家族标签只作训练目标）；家族动作为训练折上该家族按 C 最好的固定动作；叶纯度 < 0.8 回退训练 SBS；`ood` 范围为全部 20 个静态特征的训练 [min, max] 各向外扩 10% 范围，越界或静态缺失也回退训练 SBS | 深度 {3, 5}，最小叶 5 |
| PR 前缀读出 | 静态 + D 前缀（v10 B 族），base = 训练 SBS，未进入搜索时取 base | τ ∈ {0.1, 0.5, 2}；ridge α ∈ {1, 10} 或树深 {2, 3}；margin θ ∈ {0, 0.1} |
| NC 匹配对照 | D τ → 训练 SBS，τ 取 PR 内层所选，不读内容 | — |

- 删失训练规则沿用 v10：ridge 的目标为 log 成本差，超时值截在 log(3601)，两臂都超时的样本不参与该差值。树与准则 C 用实际消耗计。
- 真实家族标签直接映射到家族最佳动作，这只是事后诊断上界，不可部署。
- 不重开三臂 probe 网格。v5 与 v10 已得到负结果，本轮没有登记任何新的三臂假说。

### 7.3 验证与冻结规则

**嵌套交叉验证**：训练池 528 题按基础问题分组，以家族×档分层，外层 5 折、内层 3 折，seed 0。用 OOF 结果按准则 C 比较各方法族。

**诊断**：留一家族与留一档，各做一次外层，不用于选择。

**主策略**：按复杂度 SBS < ST < TR < PR 依次比较，候选在以下情况取代当前方法：
- 解题数更多；或
- 解题数相同且 OOF 总 CPU ≤ 当前的 0.99。

**结构对照 S\***：ST 与 TR 中按 C 较好者。若主策略就是 S\*，则主策略本身就是简单结构路由，不再另设结构对照的增量检验。
