# v11 方法比较、开发验证与冻结（S4）

数据：训练池 528 题（发现 + 开发）。规则见协议第 7 节与 [protocol.json](../../configs/broad_scope_v11/protocol.json)。结果在 [selection.json](../../results/broad_scope_v11/selection.json)，冻结记录在 [FREEZE.json](../../configs/broad_scope_v11/frozen/FREEZE.json)，tag 为 `v11-rule-freeze`（commit 99f33de）。冻结在任何确认集或公开集运行之前提交。

**模拟方式**：
- 观察部分（静态分析、D 前缀）取自真实的 MEASURE 运行（`measure_pool`，528 题），包括解析与 wrapper 自身的 CPU；
- 动作部分取该动作固定运行的实测 CPU；
- 决策都经过部署时使用的同一个 `common.decide`。

**MEASURE 覆盖**：
- 静态分析 528/528 成功，最长 1.2 s。
- D 前缀未进入搜索的题数：

  | 前缀长度 | 未进入搜索 / 528 |
  |---|---:|
  | 0.1 s | 259 |

  2 s 时这 30 题全部是 bwplan（66 题中有 30 题在 2 s 内还没开始搜索）。

**各方法在外层所选的配置**：

- TR 在外层共选出 D 486 次、F− 27 次、F+ 15 次：
  - bwplan 66 题中有 27 题被路由到 F−，其余落在纯度不足的叶子或折内动作为 D 的叶子，在 bwplan 上节省 341 s（5730 vs 6071）；

## 2. 主规则（按复杂度 SBS < ST < TR < PR 逐个比较）

| 候选 | 对比 | 是否胜出 |
|---|---|---|
| ST | SBS | 否（解题数相同，CPU 多 0.2%） |
| TR | SBS | 否（CPU 多 0.7%） |
| PR | SBS / NC | 否 / 否（少解 1 题） |

结论：
- **主策略 = 开发 SBS = 固定 D**。在线观察、结构识别与前缀读出都没有在开发验证中超过 D。
- **结构对照 S\* = ST**：按准则 C，ST 的 136 064 s 优于 TR 的 136 777 s。
  - ST 在全池上用内层 3 折 CV 选超参数（深度 1、θ = 0.25）后拟合，得到的树是单个叶子 D。部署时它等于“静态分析 + D”，只多付静态分析的开销。
  - 这是规则给出的结果，如实部署。确认中“主策略 vs S\*”实际上检验的是静态分析开销。
- **NC 不部署**：主策略不是 PR。
- **按协议第 7.3 节锁定的部署清单**：D、F+、F−（开发 SBS = D，与主策略同一记录）、W_struct（frozen/structural.json）、W_v10（原 v10 wrapper 加冻结文件，只作描述）。

## 3. 留一家族 / 留一档诊断（不用于选择）

| 方法 | 留一家族 已解 / 总 CPU | 留一档 已解 / 总 CPU |
|---|---|---|
| SBS（D） | 505 / 135 796 | 505 / 135 796 |
| ST | **439** / 370 936 | 502 / 159 125 |
| TR | 505 / 135 902 | 505 / 135 902 |
| PR | 490 / 194 520 | 501 / 154 295 |
| 家族标签 → flag | 505 / 135 796（未见家族只能用全局 SBS） | 502 / 160 478 |

**未见家族的风险**：
- 留一家族时，ST 用其余 7 个家族的数据学到的切分，把被留出的 qcp 整体送到 F+，66 题全部超时。
- PR 在被留出的 vcover 上丢 15 题。
- TR 的越界 / 低置信回退把所有未见家族的输入送回训练 SBS，因此与 D 相同。

**未见规模的风险**：留一档时 ST、PR 与“家族 × 档标签 → flag”在 L 档都会变差，原因是偏好随规模反转（见 [STRUCTURE_MAP](STRUCTURE_MAP.md)）。

**结论**：在这 8 个家族上，细粒度在线预测没有可靠增量；简单结构路由在已见家族上也没有超过 D。在未见家族或未见规模上，没有越界回退的读出器有严重误选风险。
