# R4：冻结后在新实例上验证

## 1. 设置

**验证集**：`configs/stable_selection_v6/validate_hashes.txt`，共 55 题、30 个家族组，在 R0 中只用元数据按预先规则选出。
- 这些题从未被任何旧研究运行过；与 v4 面板、v5 确认集、第一轮运行过的实例之间，hash、成员 hash 与 isohash 都已核对。
- 每年约 12 题；2023 年只有 7 道合格新题。按规模分层，规模上大 46、中 5、小 4。剩下的未曝光题几乎都是大公式。
- 其中 27 题、15 个家族组不属于 dev 的家族。没有从未曝光的家族，所以这只是“新实例、已曝光家族的有限确认”。

**冻结**：提交 `176515a`，标签 `v6-freeze`。冻结的内容包括：最终模型、阈值、清单与下载校验、代码、二进制、观察上限、分析脚本与协议的 sha256。之后才运行。

**策略**：P1|M05，即 S28 观测加“解出概率 + 条件耗时”读出器，C = 0.1、θ = 100 s。在 R3 中 8 个比较都没有正的 OOF 净收益，它作为“负对照部署”晋级；它在 dev OOF 上为 −0.00%，几乎从不偏离。

**运行**：
- 在同一批 2 个节点上，固定 D / F+ / F− 共 165 次，与 wrapper 55 次并发、交错运行。两类运行各占一个 CPU 插槽，两个节点上的插槽对调。
- 没有失败，也没有补跑。
- 我写的作业脚本在全部运行写完后没有自行退出，原因是 `pgrep` 匹配到了自身的命令行。作业被手动取消，没有影响任何记录，见协议偏离 3。
- 所有解出都通过独立检查。

## 3. 收益来自哪里

策略一共偏离了 4 次：F+ 1 次、F− 3 次。观察不完整而回退 D 的有 3 题。

- **两次正确偏离贡献了几乎全部收益**，两者都在 dev 家族上：
  - `761651d4b6`（quantum-kochen-specker）：D 超时，F+ 在 236 s 解出，省约 364 s；
  - `c8e6440436`（miter）：F− 用时 15.8 s，D 为 69.4 s，省约 54 s。
- **另外两次 F− 偏离**都在非 dev 家族 ecc-equivalence-checking 上。三个动作的耗时几乎相同，各多付 1–3 s 的观察与计时差。
- **保留 D 的题**：22 道两边都解出的题上，wrapper 中的 D 与固定 D 的成本差中位数为 −0.18 s，合计只有 +0.8 s。所以交错运行之后，计时没有系统性的偏差；单题仍有 ±20 s 的波动，例如 `e2deb375e5` 一题 183.0 对 162.8 s。

**解释**：两次正确偏离对应的结构（相关家族在 dev 中有 F± 优势的例子）是模型从 dev 中学到的；但同一个模型在 dev 的 OOF 上只偏离了 3 次，净收益为 0。所以更合理的解释是：一个极保守的模型在 55 题中碰到了 2 道恰好适合偏离的题，不能说明识别能力已经泛化。

## 4. 结论

- **不是可靠正结果**：区间含 0，收益由 2 道题决定，两者都来自 dev 家族，在非 dev 家族上为 0。
- **够不上局部正结果**：子群的支持量只有 2 题、2 个家族，不足以构成“识别出有收益的子群”。
- **对有界负结论的检验**：冻结的保守策略在新实例上没有造成损失（点估计为正），但也没有可靠收益。这与 dev 上的结论一致。
- **F± 作为固定动作**：在新实例上也都不优于 D，与 v4、v5 一致。
