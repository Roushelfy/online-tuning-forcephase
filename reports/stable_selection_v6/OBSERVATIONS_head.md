# R2：修复观测、成熟 SAT 特征对照与可解释差异

生成表格附在第 6 节：[R2_ENGINEERING_TABLES.md](R2_ENGINEERING_TABLES.md) 是工程 12 题的结果，[OBSERVATIONS_TABLES.md](OBSERVATIONS_TABLES.md) 是 dev 401 的结果。所有规律都只是开发假说，等待外部实例检验。

## 1. 修复局部搜索：可复现性已验证

- **先重现 v5 的缺陷**：v5 的局部搜索每个起点以 0.2 s CPU 截断。在工程 12 题上用 v5 当时的参数重复 3 次，**3 题**的局部搜索特征在重复之间不同，分别有 12、14、15 个特征。另外 9 题在 0.2 s 之前就跑满了 20 万次翻转上限，所以一致。
- **修复**（`tools/obsprofile6.c`）：
  - 每个起点固定翻转 W 次，并用独立的固定随机流；
  - 整段只有一个 CPU 硬上限 1.0 s，触顶时整段记为不完整，不输出半成品特征；
  - 每个起点的 CPU 单独作为计时元数据保存。
- **修复后的验证**：两种工作量下，同一输入重复 3 次，所有非计时特征都**逐项相同**——两种 W 各 12 题，没有一题出现差异。这也覆盖了同一次运行中的残余式、双边传播和蕴含图各段。
- **W 的选择**：W = 50,000 时有 11/12 题正常完成，局部搜索段中位 CPU 0.06 s，满足预先固定的规则，所以选 W = 50,000。
- **修复中发现的一个工具缺陷**（协议偏离 1）：
  - 第一次工程运行时，局部搜索段最大用了 6.3 s，远超 1.0 s 上限。原因是周期性检查调用的 `over()` 每 1024 次调用才读一次时钟，在每次翻转都很贵的超大公式上，检查间隔太粗。
  - 改为直接读时钟后重跑，最大 1.02 s。
  - 这发生在 dev 采集之前，没有读任何求解结果。

## 2. SATzilla 2024 官方特征

- **构建**：官方仓库 `hadarshavit/satzilla` 的 commit `6209d485`，在容器中从源码构建 `features`（`make clean-all && make feature`），二进制 sha256 为 `5cf3f4e0…`。仓库没有顶层许可证文件，所以只在本地调用，不并入本仓库。
- **不用的组**：
  - `ls` 和 `cl` 会调用仓库自带的预编译求解器，不用；
  - `--preprocess-timeout 0` 跳过外部预处理器，因为它同样是预编译程序。
- **选组**：在工程 12 题上逐组单独运行，每组上限 3 s。只有三组满足“≥ 9/12 题完成、中位 CPU ≤ 0.5 s”：

  | 组 | 中位 CPU | 特征数 |
  | --- | ---: | ---: |
  | ncnf-constraints | 0.08 s | 68 |
  | ncnf-rwh | 0.08 s | 14 |
  | unit | 0.15 s | 7 |

  base、structure、ncnf-graphs、dia、lp、lobjois 每组中位约 2 s，sp 为 1.2 s 且只有 8/12 题完成，都远超本轮的观察预算。文献中的特征时间预算本来就更长，这里只能取能在预算内完成的部分。
- **dev 采集与工程开销**：三组合在一起在 dev 上运行，364/401 题在 3 s 内完成，37 题触顶。全部 SATzilla 运行合计 0.13 CPU 核时，加上构建与测试，在 2 CPU 核时的工程上限之内。
- **与旧特征的重叠**：
  - `unit` 组的“按深度做单位传播后的变量减少比例”与 v5 B07 同类，但它不区分正负方向；
  - `ncnf-constraints`（门 / 约束节点的度分布）与 v5 A07 有关，并覆盖了 v5 未实施的 C05；
  - `ncnf-rwh` 是递归权重启发式。
  
  与 S28 只在规模统计上重复。

## 4. 核心机制分析：局部搜索三个起点的差异

**按单 seed 优势组看中位数**：F− 优势组（24 题）有一致的方向。
- 从全 1 起点出发，局部搜索最终的最少违例数明显更高：`l6_best_one` 中位 2.82，D 优势组为 1.79（log10 尺度）。
- 两个端点起点的下降程度都更低：`l6_desc_zero` 0.67 对 0.89，`l6_desc_one` 0.84 对 0.98。
- 全 0 与全 1 两个起点的最终赋值差别更大：`l6_agree_01` 0.44 对 0.55，`l6_ddens_01` −0.46 对 −0.06。

直观地说，在 F− 占优的实例上，局部搜索从“全 0”附近出发比从“全 1”附近出发更容易接近满足，这与“统一负向决策更有利”的方向一致。F+ 优势组相对于 D 优势组则没有明显的方向差异。

**但逐题信号很弱**：
- 与 r_F− 的秩相关在 −0.17 到 +0.16 之间；控制规模之后，或者在家族内部，相关也都只有 0.1 左右。
- 把 R1 中稳定的 15 道 F± 优势题，与规模最接近、家族不同的 D 优势题配对比较：6 个起点差异特征的差值同号比例为 57%–86%。在 7–8 对的样本上，这与随机水平分不开。

**结论**：这个组级差异作为机制假说是合理的，但它没有强到能逐题区分，也没有在 R3 的选择实验中转化成收益。

## 5. 小结

- **可复现性问题已解决**：修复后的局部搜索和全部 obsprofile6 观测可以逐项复现。
- **成熟 SAT 特征**：只有不到 0.5 s 的三组能放进本轮的观察预算，大公式上的完成率也只有 64%。
- **信号强度没有变化**：新观测与 v5 一样，只在组级上有方向一致的差异，单题信号仍然很弱。
