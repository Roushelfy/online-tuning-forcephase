## 2. 控制器与 wrapper 接入（已完成，已测试）

- **新模块与适用范围**：新模块 `scripts/run_timeout_policy.py`，已接入 v7 `longrun.py`、v8 `runner.py` 与 v9 `runner.py`。
- **限额与状态**：每个普通作业 `cap_cpu = 3600`、`cap_kind = policy_timeout`；更短的显式 oracle 界保留原值。到达上限即停止，记为 `policy_timeout`；越过上限才给出的答案也记为超时。
- **新运行 id**：运行 id 中加入了 `run_policy_id`，旧记录不会被跳过，也不会被覆盖。
- **wrapper 的计时**：wrapper 的 probe 是被等待的子进程，exec 后的正式求解是同一进程，所以观察、选择、重启与正式求解合计受同一个 3600 s 限制。
- **测试**：`tests/test_run_timeout_policy.py` 用受控子进程（伪求解器）做检查。
  - 固定臂到上限即停止；
  - wrapper 的 probe（0.5 s 窗口）与重启合计计时，而不是 probe 之后再给一个完整上限；
  - 上限内给出的答案仍由真实的 checkmodel 检查；
  - 旧运行 id 不变。

  更新后的 `tests/test_resource_policy.py` 检查三个控制器都没有累计停止、但都执行单次上限。
- **旧政策实现保留**：`scripts/resource_policy.py` 仍负责“累计不限”，不再单独作为单次运行政策。

## 3. 两种视图

- **历史无上限视图**：按各运行实际给出的完成时间，政策停止的运行作为实际 CPU 下界。
- **3600 s 视图**：
  - 已解 = 经验证的完成且 CPU ≤ 3600 s；
  - 超时 = 没有这样的完成，且有实际运行达到 ≥ 3600 s；
  - 不可重建 = 只有低于 3600 s 的历史下界（例如 v6 的 300 s 停止）。

  不用 3600 s 代替完成时间，不算 PAR2。

| 面板 | 方法 | 历史无上限：完成数 | 3600 s 内已解 | 超时 | 不可重建 |
|---|---|---:|---:|---:|---:|
| 原 55 题 | D | 49/55 | 42 | 13 | 0 |
| | P1_M05_long | 49/55 | 42 | 13 | 0 |
| | F+ | 34/55 | 32 | 9 | 14 |
| | F− | 33/55 | 31 | 9 | 15 |
| v9 留出 270 | D / F+ / F− / W_ref | 全部 270/270 | 全部 270 | 0 | 0 |
| v9 规模外推 90 | D | 90/90 | 82 | 8 | 0 |
| | F+ | 90/90 | 79 | 11 | 0 |
| | F− | 89/90 | 82 | 8 | 0 |
| | W_ref | 90/90 | 78 | 12 | 0 |
| v9 外部 60 | 全部方法 | 60/60 | 60 | 0 | 0 |

![3600 s 内的解题曲线](fig6_timeout_cactus.png)

原 55 题的 F± 曲线偏低，部分原因是 14–15 题只有 v6 的 300 s 证据，无法重建。

- **原 55 题**：
  - 3600 s 内至少一个固定动作能解出的题：46 / 55。
  - D 超时的 13 题分两部分：
    - v7 结束时 D 未完成的 8 题：恢复运行中 `c7bf3517f4`（GBD unknown）12,531 s、`7ff8c9781b` 27,170 s 完成（UNSAT）；`ac3e3bb744` 24,106 s 给出的答案因检查器内存不足未能验证；其余 5 题在约 85,000 s 时被政策停止。
    - v7 中 D 已完成、但用时超过 3600 s 的 5 题（3,808–8,696 s）。
  - 3600 s 内三个动作都解出的 23 题上：D 220 s，F+ 194 s，F− 191 s。这只是次要描述，有筛选偏差。
- **v9 留出 270 题**：没有一个运行超过 3600 s（最长约 1,300 s），所以 3600 s 视图与冻结的主比较完全相同：F+ 相对 D +45.8%，W_ref +49.7%。这是事后敏感性分析，原冻结协议和数字不变。
- **规模外推**：
  - 3600 s 内至少一个固定动作能解出：86 / 90。
  - D 的 8 个超时都在 rand3 n = 400 的 UNSAT 题和 assign2 T = 700 上；F+ / W_ref 的超时多在 assign2 T = 700 上。
  - 各方法都解出的 74 题上：D 131 s，F+ 334 s，F− 276 s，W_ref 250 s（次要描述，有筛选偏差）。
- **外部 60 题**：都远在 3600 s 以内，两种视图相同。

## 4. 之后的研究

按政策，主研究面板应以秒级到分钟级的多规模生成题为主，冻结前用独立试采样选择能在 3600 s 内覆盖的规模。冻结后不删除超时题，也不按策略赢家挑题。极难的比赛题只在统一截止下作压力测试，不阻塞主研究；特别长的个案以后另立清单和协议。
